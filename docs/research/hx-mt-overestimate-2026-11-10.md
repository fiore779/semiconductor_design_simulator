# HX 系(275HX・14700HX)の MT 過大の調査(2026-11-10)

結論: **原因は特定できなかった。係数・データは変更していない**(推測で係数を動かさない方針)。数値での切り分けと、確認に必要な取得を以下にまとめる。

## 2. 切り分け

1. **E コア寄与ではない**: 同じ Lion Cove + Skymont の 285K(P8+E16、公開値 25589)は MT +8.5% で ok。E の u(Skymont)・L3 遅延・η は 285K で確認済み(`arrow-lake-mt-2026-11-10.md`)。同じコア構成の 275HX だけ +26.7% になる。
2. **差はすべて公開値側の落ち幅とクロック係数の差**: 予測は 285K → 275HX で約 4% しか下がらない(係数 1.0 → 0.948、全コア実測クロック 5.4 は 285K のみ)のに、公開値は 0.820 倍(ST は 0.947 倍)。14700K → 14700HX は予測の落ち幅が小さいのに公開値は MT 0.660 倍・ST 0.848 倍(ブースト 5.5GHz は同じ)。
3. **係数の外挿**: 連続式 c·W^0.15 は W が 25〜120W の SKU で校正した式。HX は 157〜160W(予測 0.946〜0.948)で、校正範囲の外の延長。k(誤差 0 の係数)は 0.70〜0.75 で、他の x86 モバイル(185H 0.903・395 0.926・388H 0.869・HX 370 0.870)より大きく低い。単調増加の式とは合わない(120W までは k が W とともに増える)。式の W を k に合わせると 275HX で約 33W になり、24 コアの機体としても非現実的。
4. **W の選び方を ARK の PBP(55W)に変える案**: 係数は 0.809 になり、275HX は約 +8%(ok)、14700HX は約 +16%(ng のまま)。ただし同じ規則を 185H(PBP 45W → 0.784)に適用すると誤差は -0.0% → 約 -13% に悪化し、388H・386H も悪化する。**HX だけに別の規則を入れる根拠はない**ので採用しない。
5. **ST の過大が先にある(14700HX)**: ST +18.0% は、公開値がモバイルの全投稿平均で省電力・低クロックの機体に引き下げられていることと整合する(設計書 §13.4 ①。Notebookcheck のレビュー機と比べると 14700HX -0.3%・275HX -3.9%)。MT も同じ偏りを受けるはずで、ST の偏りを仮に全部 MT に引き継ぐと 14700HX は +35.7% → 約 +15%、275HX は +26.7% → 約 +22%(いずれもなお ng。計算上の目安で、採用はしない)。つまり 14700HX の MT 過大のおよそ 20 ポイントは ST と同じ公開値側の偏りで、残り(14700HX 約 15%、275HX 約 22%)は HX の機体の電力設定が 55W〜157W と幅広いこと(OEM の PL1/PL2 の違い)で、Geekbench の MT が長時間の持続電力に強く依存するためと推定される。これは推測で、実測の根拠はない。
6. **Geekbench の取り直しが未実施**: 公開値は直近 25 件(n=24・18)の中央値で、OS・電力設定は区別していない。HX の機体の電力設定は ARK(Base 55W / Max Turbo 160W・157W)と OEM(例: Legion Pro 7i は PL1 156W / PL2 201W)で大きく違い、Geekbench Browser は 403 で取得できない(本調査でも Chrome の取得手段がなく未実施)。**電力設定別・OS 別の再取得ができれば原因を特定できる**。

## 3.6 標本 4 件の追加と、MT 誤差の W 依存の検証(ユーザー選択 A。2026-11-11 追記)

公式ページ(Intel ARK・amd.com)の値で 13980HX・14900HX・285H・7945HX を `calib:false` で追加した(`docs/research/hx-sample-gb7-2026-11-11.md` の GB7。校正・係数は不変)。追加で既存 102 件の評価は 1 件も変わらない(評価ハッシュ 58b638ee… が追加の前後で一致)。各 SKU の出典・未取得項目は `data/presets/chips-pc.js` の notes に記載。

|---|---|---|---|---|---|---|---|

読み取れること(数値のみ。因果は断定しない):

1. **W が同じでも誤差は 9〜26% に散る**: 13980HX・14900HX・14700HX は W=157・係数 0.946 が同一なのに MT 誤差は +9.2 / +20.2 / +26.1%。「W=157 だから過大」という仮説では説明できない(W が原因なら同じ W で同じ向きの大きさになるはず)。
2. **MT 誤差は ST 誤差と一緒に動く(Raptor Lake・Zen 4・285H)**: (ST, MT)= 13980HX(+4.6, +9.2)、14900HX(+11.8, +20.2)、14700HX(+13.7, +26.1)、285H(+11.3, +19.7)、7945HX(+3.9, +4.5)。MT 誤差は ST 誤差のおよそ 2 倍。ST が合う SKU(13980HX・7945HX)は MT もほぼ合う。**275HX だけが例外**(ST +5.4% なのに MT +23.2%)。ST の過大は公開値側(モバイルの全投稿平均が省電力の機体に引き下げられる。§13.4 ①)と整合する。
3. **OS 混在値と Windows のみ値の差は SKU で逆向き**: 14900HX は Windows のみが +10.9% 高い(MT 誤差 +20.2% → +8.4%)が、13980HX は -0.9%、285H は -1.1%、14700HX は +3.8%、275HX は +1.9%、7945HX は +2.8%(いずれも Windows のみ ÷ OS 混在 − 1)。OS 混在 → Windows のみに替えても 14700HX・285H・275HX は +21% 前後のまま。
4. **Arrow Lake のモバイル 2 件は W が違っても同じ誤差**: 285H(W=115、係数 0.903)と 275HX(W=160、係数 0.948)は Windows のみ値に対し +21.1% / +20.9%。W・係数の違い(約 5%)が誤差に出ていない。W 依存ではなく、Arrow Lake のモバイル全体の共通の要因(285K のデスクトップは +8.5%)を疑う方向になる。
5. **W が小さい 7945HX(75W)は合う**: ただし 1 件で、Zen 4 の 16 コアは 7950X(+4.3%)と同程度。W の効果と Zen 4 の効果が分けられない。

結論: **HX の電力設定(mtPublishedW=range.maxW、55〜157W の幅)で MT が過大になる、という仮説は、この 4 件では支持されない**(同じ W で誤差が散る、Arrow Lake のモバイルは W に依らず +21%)。原因は未特定のまま。係数は動かしていない。次の候補は、(a) Arrow Lake のモバイル(Lion Cove+Skymont の SKU 間で共通)の MT の過大の要因、(b) 14700HX と 14900HX の差(同じダイ・同じ W で +26% と +20%。公開値の標本の偏りか)、(c) 275HX の ST と MT の乖離。
