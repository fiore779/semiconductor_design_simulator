## 1. データ源の調査結果(2026-11-20、Geekbench Browser をブラウザで確認)

### 1.1 Geekbench 7 の GPU(主指標)
- 個別結果ページ: `/v7/gpu/<ID>`。**GPU スコアと 11 項目**(背景ぼかし・顔追跡・超解像度・水平線検出・写真フィルター・ビデオフィルター・RAW・特徴マッチング・パストレーサー・素粒子物理学・流体シミュレーション)、OpenCL 情報(デバイス名・計算ユニット数・最大周波数・デバイスメモリ)が取れる。
- 検索: `/v7/gpu/search?q=…&page=N`(25 件/ページ)。**行にはシステム名・CPU・OS・API(CUDA / OpenCL / Vulkan / Metal)・スコアだけで、GPU 名は出ない**。GPU 名で絞るには検索語が GPU 名に当たることに頼るか、詳細ページ(1 件ずつ)を開く必要がある。例: 「RTX 4070」で 4,782 件、API は CUDA・OpenCL・Vulkan が混在し、Laptop の結果も混ざる可能性がある(未確認)。
- **チャート**: `/vulkan-benchmarks`(約 1,250 デバイス)・`/opencl-benchmarks`(約 1,660)・`/metal-benchmarks`・`/gpu-benchmarks`(iOS)。Geekbench 7 の GPU スコア(基準 RTX 4060 = 100,000)。**5 件以上の固有結果があるデバイスだけ**、平均スコア。`/v7/cuda-benchmarks` 等は 404(CUDA のチャートは無い)。
  - 例(Vulkan): RTX 5090 376,009 / RTX 4070 SUPER 203,039 / RTX 4070 175,739 / RX 7800 XT(RADV)143,060 / RX 7900 XTX 198,391 / RTX 4060 Ti 123,791。
  - 例(OpenCL): RTX 5090 374,554 / RX 7900 XTX 215,111 / RX 9070 XT 168,710 / RX 6800 XT 167,405 / Arc B580 84,895。
  - **API で別物**: RX 7900 XTX は Vulkan 198,391・OpenCL 215,111。RTX 5090 は Vulkan 376,009・OpenCL 374,554。同じ GPU でも API 間で ±10% 程度ずれる。
  - **同じ GPU がドライバ名違いで複数行**(例: `AMD Radeon RX 7900 XTX (RADV GFX1100)` 212,459 / `Radeon RX 7900 XTX` 198,391)。Linux の Mesa(RADV・radeonsi・NVK)は Windows ドライバと別集計。
  - iGPU も載る(Radeon 890M は Vulkan 20.5〜20.8k・OpenCL 31.1k、780M は Vulkan 33.7〜37.8k)。**iGPU は API で 1.5 倍違う**ので、API の指定が必須。
- 区分: チャートは Primate Labs の集計(平均)で **[公表]**(提出結果の平均。CPU のような中央値方式の [実測] ではない)。中央値が必要なら検索の個別結果から自分で取る([実測])。

## 2. 設計案

### 2.1 範囲
- 1 段階: **デスクトップ dGPU の代表 SKU**(NVIDIA RTX 50/40/30、AMD RX 9000/7000/6000、Intel Arc Alchemist/Battlemage)。ノート向け(TGP 違い)・ワークステーション・データセンターは後回し。
- 2 段階: iGPU(メモリ帯域と電力をパッケージで共有。GB7 の iGPU は API で 1.5 倍違うので API 固定が必須)。

### 2.2 スコアの定義
- 主 API は **Vulkan**(NVIDIA・AMD・Intel を同じ API で比べられる。CUDA はチャートが無い)。OpenCL は副。Metal は Apple 用で別系列(iGPU の段階)。
- 検証値の取り方: (a) チャートの値([公表])を一次、(b) 標本が多い SKU は検索から Windows の結果の中央値を取って突き合わせ([実測])。Linux(RADV・NVK)の行は混ぜない。
- 3DMark は別列([二次])。

### 2.3 モデル(CPU と同じ方針: 世代ごとの補正 u を中央値で学習 → 検証)
`GPU スコア = u(uarch) × 演算ユニット数 × クロック × min(1, 帯域上限比)`
- uarch ごとの u は SKU の中央値(学習内の値であって検証ではない)。SKU 別の特別な係数は入れない。
- **メモリ帯域の上限**(設計書 §5.2.2 の帯域キャップ)を最初から入れる。dGPU は帯域がスコアに効く(RTX 4060 Ti 128bit と 4070 192bit など)。
- 演算ユニットの単位が世代で違う(SM・CU・Xe コア・WGP)ので、uarch に「1 ユニットあたりの FP32 レーン数」を持たせて、**FP32 レーン数 × クロック(理論 TFLOPS)**を共通の尺度にする案が有力。
- 電力: 公表 TGP を基準に、クロックと電圧の関係でスケール。

### 2.4 ダイ・面積
- 写真の枠は CPU と同じ仕組み(tf)。ブロックは SM・CU などの単位。ダイ写真は Fritzchens Fritz・TechInsights・Kurnal などの出典を調べる。

## 5. 追加調査(2026-11-20。既定案「チャート平均を一次」の検証。**既定案は成立しない**)
- **チャートの同名 GPU の値が割れる**: Vulkan チャートで RX 7900 XTX は 198,391 と 134,680(同名 2 行)、RTX 3080 は 173,171 と 146,976、RTX 3090 は 191,730 と 179,816。さらに **RX 7800 XT は 69,620、RX 9070 XT は 99,934**(同じ AMD の RADV〔Linux〕では RX 7800 XT 143,060)。Windows の AMD の Vulkan 行は他の行と整合せず、平均が壊れているとみられる。チャートの 1 行 = 1 つの GPU 名の平均で、OS・ドライバ・クロックの混在を除けない。
- **検索(`/v7/gpu/search?q=`)は GPU 名で絞れない**: 「RX 7800 XT」で Windows/Vulkan の 12 件を取って詳細ページを開くと、デバイス名はすべて **NVIDIA GeForce RTX 4070**(検索語は GPU 名以外の項目や曖昧一致に当たる)。同じ「RTX 4070」の Windows/Vulkan でもスコアは 41,624〜170,899 と広くばらつく。
- **詳細ページ**にはデバイス名・計算ユニット(RTX 4070 = 46)が取れる(最大周波数は日本語表記の取り違えで未取得)。GPU 名で絞った中央値を取るには、検索結果の全件の詳細ページを開いて**デバイス名で振り分ける**しかなく、検索の母集団は GPU 名と無関係なので、特定 SKU の標本を集めるのは効率が悪い。
- 結論: 「Vulkan で SKU ごとの検証値を作る」のは、チャート・検索のどちらからも信頼できる値が取れない。代替案は次のとおり(要決定)。
  1. **OpenCL を主**にする(チャートの NVIDIA・AMD・Intel の値が整合している。例: RX 7900 XTX 215,111・RX 6800 XT 167,405・Arc B580 84,895・RX 9070 XT 168,710)。
  2. **NVIDIA は CUDA** も使う(検索でも Windows/CUDA の中央値が取れる。RTX 4070 は 275,715〔n=29。Ti・SUPER・Laptop の混入あり〕)。ただし API 間でベンダーが比べられない。
  3. Vulkan のまま、**チャートの Linux(RADV)行**を使う(AMD は Windows 行より整合するが、Linux 固有の値になる)。
