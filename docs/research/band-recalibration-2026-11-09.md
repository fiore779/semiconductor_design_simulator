# mobile-pc の MT 帯係数の再校正(2026-11-09)

ユーザー指示: 「395 と 258V は取得範囲を広げて取り直す。帯係数の再校正はその後」。`js/sim/perf.js` の `MT_CLOCK_BANDS`(mobile-pc の TDP 帯別の持続クロック係数)を、公開値を取り直した後の逆算で再校正した。係数の値は逆算の結果で、実装上の判断(ユーザーが指示したのは再校正)。**公開値はチャート値ではなく、検索結果の全体中央値**(2026-11-07 に直近 25 件、395 と 258V は 2026-11-09 に 200 件)。推測・未検証。

## 1. 先に行った 395・258V の取り直し(`gb7-recollect-wide-2026-11-09.md`)

| SKU | 公開値 旧(11-07、25 件) | 新(200 件の全体中央値) | n |
|---|---|---|---|
| Ryzen AI Max+ 395 | 2764 / 29916 | **2650 / 23661** | 171(PRO 395 と仮想マシン 29 件を除外) |
| Core Ultra 7 258V | 1957 / 9807 | **2268 / 10109** | 200(除外なし) |

設計書 §2.4 の該当行と `data/benchmarks/gb7-scores.js`(`tools/extract-gb7.js` で再生成。他の 169 行は不変、変わったのは 2 行の single / multi / n だけ)を更新した。11-07 に書いた「395 は 1 機種に偏る・258V は Linux 異常」の注意は、範囲を広げて解消した旨に更新した。

## 2. 再校正

標本は既存のテスト(`tests/perf.test.js` の帯テスト)の定義どおり 11 件(id の除外ルール据え置き): MT を計算でき、GB7 マルチと公表電力がある mobile-pc。**除外**: 7840HS、Kraken Point、MT を新たに計算できた 5 件(268V・258V・256V・388H・275HX)。各 SKU について「予測 = 公開値」となる係数を二分法で逆算し、帯内の中央値を小数 2 桁に丸めた。

| 帯 | n | 旧係数 | 逆算の中央値 | 新係数 | 係数との差 |
|---|---|---|---|---|---|
| 帯 0(公表電力 60W 以下) | 5 | 0.69 | 0.8398 | **0.84** | -0.0002 |
| 帯 1(60W 超) | 6 | 0.76 | 0.8058 | **0.81** | -0.0042 |

(取り直し前の 2026-11-07 時点の中央値は、帯 0 が 0.7323、帯 1 が 0.7783。取り直しで 0.8398 / 0.8058 に上がっていた。係数と中央値の差は旧 +0.1498 / +0.0458 から -0.0002 / -0.0042 になり、もとの意図「帯の係数がデータから再現できる(差 < 0.01)」に戻った。)

`MT_CLOCK_BANDS` のコメントに標本・日付・「チャート値ではなく検索結果の全体中央値」を書いた。電力未取得の mobile-pc のフォールバック 0.81 と、スマホ SoC の係数 0.91 は変えていない。

### 注意: 帯の逆転

新係数は帯 0(0.84)> 帯 1(0.81)で、**TDP を下げるほど MT が上がる逆転**が起きている(旧は 0.69 < 0.76 で下がった)。逆算の中央値をそのまま採用した結果で、物理的には不自然。`tests/tdp-select.test.js` は事実(逆転)を固定した。単調にする(帯を揃える、帯 0 を 0.81 にする等)かは判断待ち。

## 3. LOO と一律 0.81 との比較

| 指標 | 値 |
|---|---|
| LOO MAE(帯別。自分を除いた帯内中央値を小数 2 桁にして予測) | 0.1119 |
| 一律 0.81 の MAE | 0.0890 |
| LOO 誤差が 10% 超 | 5 件 |

- 395・258V を取り直す前は LOO 0.1288・一律 0.81 は 0.1063(11-07 の値)。取り直しで LOO は 0.115 を再び下回った(閾値は動かしていない)。
- **成立しない主張: 「帯別の LOO が一律 0.81 より小さい」は成り立たない**(0.1119 > 0.0890)。閾値は緩めず、`perf.test.js` に「帯別が一律 0.81 より悪い」という事実を固定し、逆転したら見直すようにした。帯を分けるより一律 0.81 のほうが誤差が小さい、というのが現状のデータの結論。
