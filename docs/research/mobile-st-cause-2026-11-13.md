# モバイル x86 の ST 過大: 原因の分解と修正案の試算(2026-11-13)

- 対象コミット: **b2a8a08**(Arrow Lake のリング接続 E の u = Lion Cove × 0.90 を入れた後)。作業ツリーには別担当の未コミット変更があるため、`git archive b2a8a08` を scratchpad に展開して評価した。**コード・データ・設計書・git は変更していない(試算のみ)**。
- 校正の状態(再計算して確認): σ=0.03306、γ=0.30、連続式 c=0.411・指数 0.15、Lion Cove u=102.13、Golden/Raptor uCal=116.5、Zen 3 u=105.73、Zen 4 131.48、Zen 5 113.70、x86 ISA 平均 u=109.18。全 158 判定のうち ng 30(ST 18 / MT 12)。
- 方法: `tests/helpers.js` と同じ読み込みで `E.makeContext()` を作り、`perf.stScore` / `mtScore` に渡すクロック・params・uarch だけを差し替えて試算した。使い捨てスクリプトは scratchpad の `load.js`・`main.js`・`harness.js`・`exp.js`・`exp2.js`・`exp3.js`・`table.js`。
- データの区分: GB7 公開値 = **[実測]**(Geekbench Browser の Windows 投稿の中央値。`gb7-windows-only-2026-11-13.md`)。NBC の GB6 ラボ値と PL1 = **[実測]**(Notebookcheck の測定と設定値。`nbc-gb7-mobile.md` §2.2、`cooling-class-power-2026-11-12.md` §4-1)。予測値・実効クロック・「最良条件の推定 GB7」・試算の誤差 = **[推定](モデル計算)**。因果の解釈は **[推測]** と書いた。
- 「確認済み」は今回、数値として再計算・照合したもの。「推測」は数値から読んだ解釈で、出典のある実測で裏づけていないもの。

## 0. 結論(要約)

1. **モバイル x86 の ST の過大は、22 SKU で一貫して約 +10%(中央値 +10.0%)。デスクトップの非代表 21 件の中央値は +0.3%**(確認済み)。公開値から逆算した実効クロック ÷ 最大ブーストは、モバイルが中央値 **0.9035**(0.817〜0.953)、デスクトップが 1.000(非代表 0.997)。
2. **この比は TDP 区分・世代ではほとんど説明できない**(確認済み)。HX 0.922、それ以外 0.899 で、HX を除いた 17 件では base W・PL1 との順位相関が 0.20・0.14 と弱く、年(世代)とは -0.05。**「モバイルは一律に約 0.90」**という形になる。
3. **最も説明力が高いのは公開値の母集団(Windows のノート PC 投稿の中央値は、最良条件の機体より低い)**。NBC のラボ測定の GB6 から最良条件の GB7 を推定すると(16 SKU)、最良 ÷ 公開値は中央値 **+7.6%**、予測 ÷ 最良は中央値 **+3.4%**。対数で見ると、過大の約 77% が母集団で説明できる。Intel(10 SKU)ではほぼ全部が母集団で説明でき(最良 ÷ 公開値 +9.2%、予測 ÷ 最良 +0.5%)、最良条件の機体は最大ブーストに届いている(実効 f ÷ boost 0.985〜1.018)。原因(電源モード・OEM のプロファイル・バッテリー駆動・低 PL1 の機体)を個別に分けるデータは無い(推測)。
4. 2 番目は **AMD のモバイル固有の残り**(予測 ÷ 最良の中央値 +6.7%。Zen 5 の 3 件で +5.8〜+8.3%、Zen 3/3+ で +6.3〜+11.1%)。最良条件の機体でも実効 f ÷ boost は 0.89〜0.94。3 番目は **モデルに無い LPDDR5X・SO-DIMM の DRAM 遅延**(モデル自身の感度で -0.7〜-5.4%。LPDDR 系は約 -3.5%)。デスクトップ代表の偏り(e)は、デスクトップとモバイルの差を作らない(Zen 3 と Zen 4 だけは約 +3 ポイントの可能性)。標本(d)の影響は ≤1.8 ポイント、SMT・OS(c)の影響は 0。
5. **推奨(実装しない。ユーザー判断)**: x86 の mobile-pc だけ、ST のクロックに **0.90 [推定・校正値]** を掛ける(評価時のみ。u の校正・MT・Apple・Windows on Arm には掛けない)。スマホ SoC の MT クロック係数 0.94 と同じ「公開値の条件での実効クロック係数」の扱い。試算では ng 30 → 19(モバイル x86 の ST の ng 11 件がすべて ok)、ok→ng は 0 件。1 件抜き(LOO)の係数は 0.9029〜0.9042 でほとんど動かず(LOO MAE 2.34%、学習内 2.27%)、過学習ではない。MT は変わらない。

- **モバイルでは比が一貫して低く、デスクトップと約 10% 離れている**(確認済み)。HX は少し高い(0.92)。ただし HX を除くと、TDP・PL1 との相関はほぼ消える。世代とメモリ種別(LPDDR かどうか)とは無相関。
- 電力・L3・ブーストの相関は、主に「HX(高電力・大 L3・高ブースト)対 その他」の差から来ている。互いに強く絡んでいるので分離できない。デスクトップでは L3 が小さい SKU(2200G・2400G 4MB、12100 12MB)が過大側ではなく、比はむしろ 1 以上(過小側)。**「L3 が小さいほど過大」というモデルの欠陥とは読めない**(推測)。
- **同じ uarch で同じブーストでも比が違う**: 285H 0.849 と 275HX 0.921(どちらも Lion Cove・5.4GHz。L3 24MB 対 36MB の差はモデルで -0.9% だけ)。14700HX 0.896 と 14900HX 0.922。どちらも PL1 中央値の低い方が低い(74W 対 130W、95W 対 130W)。SKU ごとの搭載機の構成の差とは整合する(推測)。

**最良条件の機体と比べると(§2.4 の推定。[推定])**: Intel 10 SKU では、最良条件の推定 GB7 から逆算した実効 f ÷ boost は 0.944〜1.018。Lunar Lake 3 件、14700HX、185H は 0.997〜1.018 で、**最良条件の機体は最大ブーストに届いている**。したがって「チップが最大ブーストを出せない」のではなく、**公開値(Windows 投稿の中央値)の母集団の中央が最大ブーストより約 10% 低い条件で走っている**という形になる。AMD は最良条件でも 0.885〜0.98(§2.6)。

→ (a) は、**チップ単位の意味(最大ブーストに届かない)では Intel について否定的、母集団の意味(投稿の中央値は実効で 0.90)では支持**される。比は TDP 区分・世代ではほとんど説明できない(HX と それ以外の 2 段 0.92 / 0.90 が限度)。

### 2.2 (b) モバイルのメモリ(LPDDR・SO-DIMM の遅延・帯域)と L3

- **L3 はモデルに入っている**(`cfg.l3MB`。ST は 1 CCD 分)。L3 の差は兄弟比に含まれていて、たとえば 285H と 275HX の差は -0.9%。
- **DRAM 遅延は入っていない**: `dramNs` は全 SKU で 85ns。メモリ構成の補正(`memory.js`)は「選んだ構成 ÷ 基準構成」の比なので、基準構成のプリセットでは係数 1 になる。LPDDR5X の 185H も DDR5 の 9700X も同じ遅延で計算している(確認済み)。
- モデル自身の感度で試算した(`memory.js` の LATENCY_NS: DDR5 SO-DIMM 90ns、LPDDR5X 120ns、LPDDR5 125ns を、デスクトップ DDR5 の実測 77ns〔`memory-scaling.md` §1-A #1〕との比で dramNs に掛けた。DDR4 は比 1)。

| メモリ | 該当 SKU | ST の変化(モデル) |

| LPDDR5X(固定・オンボード) | LNL 3 件、PTL 4 件、185H、未設定の 285H・325・320・395・14900HX | -2.3〜-5.4%(LPDDR は -3.4〜-3.9%) |
| DDR5 SO-DIMM | HX 4 件、7840HS、7735HS、HX 370、350 | -0.7〜-1.7% |

- 全モバイル x86 の ST に入れると(試算 vi)、ng 30 → 24(268V・388H・7840HS・358H・325・320 が ok)。ok→ng は 0 件。モバイルの中央値は +10.0 → +7.0% で、**過大の約 3 割**。MT にも入れると LNL の 3 件が ok→ng になる(MT はすでに過小のため)。
- 実測の遅延弾性は -0.05〜-0.2(`memory-scaling.md` §4-B。GB7 の ST の実測は 0 件)で、モデルの値(約 -0.08)は下側にある。弾性が -0.2 なら最大で約 -8% になる。ただし相関では、LPDDR かどうかと比はほぼ無相関(0.07)。DDR5 SO-DIMM の HX(比 0.92)も LPDDR の LNL(0.89〜0.91)も同じように過大なので、**メモリは主因ではなく、上乗せの 1〜4 ポイント**(推定)。

### 2.3 (c) SMT・OS・Windows の電源プラン

- **SMT**: ST のモデルは 1 スレッドで、SMT を使わない(γ は MT だけ)。影響は 0(確認済み)。
- **OS**: 公開値は 2026-11-13 にデスクトップ・モバイルとも Windows のみの中央値にそろえた。OS の差はデスクトップとモバイルの差を作らない(確認済み)。
- **電源プラン・OEM のプロファイル・バッテリー駆動**: Geekbench Browser の投稿に電源の情報は無いので、**直接は測れない(未取得)**。間接的には、NBC のラボ(接続電源・高性能の設定と考えられる。NBC の方針は未確認)の GB6 の ST は、ラボ内でのばらつきが 2〜8% と狭い。それにもかかわらず、Windows 投稿の中央値は最良条件より中央値で 7.6% 低い(§2.4)。そして、PL1 中央値が低い SKU ほど差が大きい(最良 ÷ 公開値と PL1 の Spearman は -0.49、n=10)。これは、省電力の設定・バッテリー駆動・低 PL1 の機体が投稿の中央を下げているという解釈と整合する(推測)。ハイブリッドの Intel で E コアに、Zen 5 の機種で Zen 5c に ST のスレッドが載る投稿が混ざる可能性もある。これは分布を見ないと判断できない(未取得)。

### 3.3 MT への連動

- (i) の形(ST だけ)なら MT は不変。MT の連続式 c=0.411 は、モバイルの標本 11 件の公開 MT に合わせた値で、母集団の差はすでに c に吸収されている。
- (iii) の形(ブーストのデータ自体を下げる)では、c を据え置くと MT が一律に約 -4 ポイント下がり、MT がすでに過小な LNL 3 件と 350 が ok→ng になる。c を再校正すると(0.431)ST・MT とも (i) とほぼ同じ結果になる。**データ(ブースト)は [公表] の値を保ち、係数をモデル側に置く (i) の方が筋がよい。**
- ST を下げたあとの MT/ST 残差: 14700HX(MT +16.0)は、ST の不足を除くと MT 自体の過大になる(`hx-mt-cause-analysis` の「ST の不足が MT に乗る」は、ST 側を合わせると「MT の c が 14700HX の母集団に対して高い」という見え方に変わる)。7840HS(-11.0)・HX 370(-19.8)の MT の過小は、ST と無関係に残る。5800U は ST・MT とも +20% で、ST の係数を入れても MT +20.3% はそのまま。**MT の ng 12 件は、この修正では変わらない**(確認済み)。

### 4.2 推奨する修正(実装しない。ユーザー判断)

1. **(モデル項・係数)x86 の mobile-pc の ST だけに、実効クロック係数 0.90 を掛ける** — 区分は **[推定・校正値]**。

3. **(説明文)`chips-pc.js` の `MOBILE_X86_ST`(2026-11-07 のチャート値の時代の文面)を、今回の分解(母集団の差 +7.6%、モデル側の残り Intel 約 0・AMD 約 +7%)に更新する候補**。errCause は数値を変えないので、判定には影響しない。
4. 採らない案:
   - (iii) ブーストのデータを下げる: [公表] の値を崩す。c を再校正しないと MT が ok→ng 4 件。
   - (iv) 公開値を最良条件の推定に置き換える: 推定は GB6 ラボ × k の [推定] で n が小さく、[実測] の公開値を置き換える根拠として弱い。参考値(gb7Ref)として並べるのに留める。

### 4.3 副作用と注意

- シミュレーターのモバイルの ST は「Windows の典型的な投稿の中央値」になり、NBC のレビュー機(最良条件)より 7〜10% 低く出る。画面の注記(errCause や確度の説明)で、この意味を明示する必要がある。
- ユーザーが mobile-pc の x86 設計を編集すると、係数がそのまま掛かる(公開値の条件での予測という意味で一貫している)。
