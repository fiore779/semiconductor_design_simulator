# Ryzen X3D(3D V-Cache)のプリセット追加の調査と試算(2026-11-15)

ユーザー指示「Ryzen X3D も追加して」。今回は**調査と試算だけ**(プリセット・コード・設計書は変更していない)。実装は別担当。

- **1 CCD の 3 件(5800X3D・7800X3D・9800X3D)はデータの追加だけで ±10% に入る。** L3 96MB を `cfg.l3MB` に入れるだけで、perf.js の L3 容量の効き方(容量^-0.5)が V-Cache の ST 向上をおおむね再現する(モデル +1.4〜3.0%、実測 +1.7〜4.5%。§2.2)。
- **V-Cache の L3 遅延 +4 サイクル**([公表] AMD・[二次] Chips and Cheese)は、入れると ST・MT が 0.5〜1.2% 下がる。許容内の判定はどちらでも変わらない(§3)。入れるかはユーザー判断。
- 既存プリセット 106 件の ST・MT は、仮のプリセットを足しても**1 件も変わらない**(追加分は `calib:false` で、校正〔u・σ〕に入らない。§3.1)。

### 1.3 ブーストが通常版より低い事情 [二次]

- 5800X3D(4.5GHz、5800X は 4.7GHz): V-Cache ダイが 1.35V を超える Vcore に耐えないため、その電圧で出せるクロックにした(AMD の説明。TechPowerUp 5800X3D レビュー p.1)。積層の構造用シリコンがコアの熱抵抗を上げる(TechPowerUp 9950X3D レビュー p.1)。
- 7800X3D(5.0GHz): V-Cache はコアと同じクロックで動くので安定する上限がある、Tjmax も 89°C に下がる(TechPowerUp 7800X3D レビュー p.1)。各コア 5050MHz に上限(同 p.26)。
- 9800X3D(5.2GHz、9700X は 5.5GHz): V-Cache を CCD の下に移して熱の問題を解消し、ベースは 4.7GHz に上がったが、ブーストは 9700X より 300MHz 低いまま(Chips and Cheese)。
- 2 CCD 品: V-Cache の無い CCD が高いクロック(5.7GHz)を受け持つ。V-Cache 側は 7950X3D で約 5.25GHz(TechPowerUp 7800X3D レビュー p.26「the 7950X3D will boost up to 5250 MHz easily with light loads on it's 3D VCache chiplet」[二次])。9950X3D は「cores with 3D V-Cache are clocked a bit lower」「The rated 5.7 GHz is reached only with a single non-cache core loaded」(TechPowerUp 9950X3D レビュー p.25)で、V-Cache 側の数値は未取得。**AMD 公式は CCD ごとのクロックを公表していない**(未取得)。

### 2.3 V-Cache による ST の向上(点/GHz の比。実測 vs モデル)

モデルの比は、通常版のプリセットのコア設計で L3 を 96MB にし、両方を実測のクロック中央値で計算した「点/GHz」の比(`P.stScore` に `fGHz` を渡す。u は通常版と同じ)。「クロック差だけ」は L3 32MB のまま X3D のクロックにしたときの比(DRAM 遅延 ns が一定なので、クロックが低いと点/GHz が少し上がる分)。

同じクロックでのモデルの L3 96MB の効果(ST): Zen 3 +2.8〜3.0%(+4cyc で +1.6〜1.8%)、Zen 4 +2.4〜2.6%(+1.8〜2.0%)、Zen 5 +1.9〜2.0%(+1.3〜1.4%)。Zen 5 ほど小さいのは、Zen 5 の ST の CPI のうちメモリの項が小さいため(32MB・実測クロックで CPI 内訳 Zen 3: base 0.114 / 分岐 0.042 / メモリ 0.078、Zen 4: 0.167 / 0.042 / 0.060、Zen 5: 0.125 / 0.042 / 0.039)。

読み取り:
- **Zen 4 はモデルと実測が合う**(実測 1.017、モデル 1.022〜1.028)。
- **Zen 3・Zen 5 はモデルが実測より 1〜3 ポイント小さい**(5800X3D 1.045 対 1.021〜1.033、9800X3D 1.044 対 1.016〜1.021)。ただし同じ Zen 3 の 5700X3D は 1.020 でモデルと合い、SKU 間で ±2 ポイントほどばらつく(機種〔ゲーム向けの機体で EXPO メモリ〕の違いなどを分離できていない)。
- 差は ST の誤差 ±3% に収まる大きさで、**L3 容量の効き方(perf.js の capExp・mpkiL3)を X3D のために変える根拠にはならない**(変えると全 SKU に効く)。
- 2 CCD 品: 9950X3D の ST の投稿は 96% が 5500MHz 以上(V-Cache の無い CCD で動いている)で、比は 1.008 とほぼ通常版。**7950X3D は投稿が 2 群に分かれる**(§2.4)。

## 3. モデルの試算

### 3.1 方法

`tests/helpers.js` の `D` を読み、既存プリセットのコピー(メモリ上)を `calib:false` で `D.presets` に、公開値を `D.gb7Scores` に足して `E.makeContext()` → `E.evaluate(design.fromPreset(p), ctx)`。スクリプトは作業用の一時ファイル(リポジトリ外)で、リポジトリは変更していない。

- 元にしたプリセット: 5800X3D ← 5800X、7800X3D ← 7700、9800X3D ← 9700X、7950X3D ← 7950X、9950X3D ← 9950X(uarch・dramLat・memory は元のまま)。変えたのは `cfg.l3MB`(96 / 128)・base/boost(公式)・allCoreGHz(下の表のとおり)。2 CCD 品は `l3Ccds: 2` のまま。
- 「+4cyc」: 試算用の uarch 記録「Zen 3 (X3D)」等を作り(`uFrom` で元の uarch の u を借りる)、`l3Lat` を元 +4(Zen 3: 46→50、Zen 4: 未設定〔既定 40〕→44、Zen 5: 46→50)にした。
- **既存プリセット 106 件の ST・MT は、仮のプリセットを足す前と後で 1 件も変わらない**(σ = 0.031512 のまま)。

基準(既存プリセットの現状): 5800X ST 0.00%・MT +8.48%、7700 ST 0.00%・MT -1.71%、7950X ST +5.97%・MT +0.94%、9700X ST 0.00%・MT +2.33%、9950X ST +0.50%・MT +5.33%。

### 3.4 試算から分かること

1. **V-Cache の ST への効き方は、今の perf.js の L3 容量の項(容量^-0.5)でおおむね出る**(1 CCD 品で ST 誤差 -2.6〜+2.4%)。足りない分(Zen 3・Zen 5 で 1〜3 ポイント)は SKU のばらつきの範囲。GB7 は大容量キャッシュの効くゲームとは違い、効果は小さい(実測 +1.7〜4.5%)。
2. **L3 遅延 +4 サイクルは小さい**(ST -0.5〜-1.2%、MT -0.5〜-1%)。Zen 3 の ST は実測に近づき(+1.95 → +0.78%)、Zen 5 の ST は遠ざかる(-2.06 → -2.57%)。判定は変わらない。
3. **MT の誤差は通常版と同じ傾向**(5800X3D は 5800X の +8.5% と同じく高め、9950X3D は 9950X の +5.3% より +4 ポイント高い。PPT 230W は同じなので、V-Cache 側の CCD のクロックが低い分と読めるが、出典のある全コアクロックが無い)。
4. **7950X3D の ST は今の perf.js では合わない**: 最速コア(topCore)= boost 5.7GHz で、L3 = 128 ÷ 2 = 64MB として計算するが、実際の投稿の過半は V-Cache 側(約 5.23GHz・96MB)で動き、残りは通常 CCD(5.7GHz・32MB)で動く。V-Cache 側で計算すると +3%。

## 4. 実装に必要な変更

### 4.1 データだけで済む(5800X3D・7800X3D・9800X3D、注記つきで 9950X3D)

- `data/presets/chips-pc.js` にプリセット 4 件(`calib:false`)。cfg: cores(uarch は既存の 'Zen 3' / 'Zen 4' / 'Zen 5')、`l3MB: 96`(9950X3D は 128・`l3Ccds: 2`)、`l3Note`(32MB + 積層 64MB。2 CCD は片側だけ)、`l2`、memory(公式の 2x1R の速度・2ch)。power: base = TDP [pub]、peak = PPT [sec](5800X3D は PPT 未取得なので peak をどうするか判断が要る)。`dramLat` は §1.5。`allCoreGHz` は 5800X3D 4.4(KitGuru)・9800X3D 5.22(TechPowerUp)だけ。
- dies: CCD・IOD・V-Cache ダイ。面積は §1.1・§1.2(公式の CCD/IOD と既存の値の食い違いをどうするかは判断が要る)。Zen 5 の V-Cache ダイは面積未取得(C2 は数値のダイが 1 個あればよい)。
- GB7: 設計書 §2.4 の AMD の表に 5 行(n・取得日・方法)を足し、`tools/extract-gb7.js` で `data/benchmarks/gb7-scores.js` を再生成(手編集しない)。
- `data/blocklib.js`: Zen 5 の CCD の行は `chips: ['amd-zen5-9700x', 'amd-zen5-9950x', 'amd-strixhalo-395']` と SKU を列挙しているので、9800X3D・9950X3D の id を足さないとコア部品が「不明」になる。Zen 3・Zen 4 の行は `chip: null`(全 SKU 共通)なのでそのまま当たる。
- 既存 SKU への影響: なし(calib:false なので u・σ・連続式の c は動かない。試算で確認)。

### 4.2 L3 遅延 +4 サイクルを入れる場合(任意。ユーザー判断)

最小案は 2 つ:
- (a) **データだけ**: uarch.js に「Zen 3 (X3D)」「Zen 4 (X3D)」「Zen 5 (X3D)」を足す(`uFrom` で元の u を借り、`l3Lat` を元 +4)。perf.js は変えない。ただし blocklib の行(uarch 名で引く)・UI の uarch 一覧にも 3 件増える。Zen 4 は元の `l3Lat` が未設定(既定 40)なので「44」は既定値 + 4 になる(Zen 4 の L3 遅延の実測は未取得)。
- (b) **perf.js に cfg の項目を 1 つ**(例: `cfg.l3ExtraLatCyc: 4`。stScore で `u.l3Lat` に足す)。uarch を分けずに済む。無い SKU は不変。
- どちらも効果は ±1% 程度で判定は変わらない。物理的には正しい(出典あり)が、Zen 5 では ST の誤差が少し広がる。

### 4.3 2 CCD の非対称(7950X3D に必要。9950X3D は改善)

perf.js の変更が要る。最小案:
- cfg に CCD ごとの L3(例: `l3PerCcdMB: [96, 32]`)と、cores の各エントリに `ccd`(0 / 1)を持たせ、CCD ごとのクロック(V-Cache 側 / 通常側の boost・allCore)を別エントリで書く。
- stScore: ST を動かす CCD を `cfg.stCcd` で指定し、その CCD の L3(÷1 スレッド)とクロックで計算する(無ければ従来どおり topCore・l3MB÷l3Ccds)。
- mtScore: 各エントリの L3 を「自分の CCD の L3 ÷ 自分の CCD のスレッド数」にする(Lunar Lake の l3Types と同じく、項目を持つ SKU だけ変わる)。
- 影響: 項目を持たない既存 106 件は不変(l3Types と同じ作り)。
- 根拠: §2.4 の 2 群(V-Cache 側 93 件・5228MHz・482.0 点/GHz、通常側 84 件・5701MHz・466.8 点/GHz)、TechPowerUp の「片側だけ V-Cache」。**ただし V-Cache 側のクロック 5.25GHz は [二次](TechPowerUp の本文)で AMD 公式に無い**。9950X3D の V-Cache 側のクロックは未取得。

## 6. 限界・未取得

1. **Maximum Frequency は最大値で持続クロックではない**(点/GHz は最大クロック基準)。2 CCD 品の「どちらの CCD で動いたか」はクロックからの読み([推定])。
2. **X3D と通常版の点/GHz の比は、機種・メモリの違いを分離していない**(X3D はゲーム向けの機体が多い)。5800X3D(1.045)と 5700X3D(1.020)の差がその幅の目安。
3. **ダイ面積の食い違い**: AMD 公式の CCD(Zen 3 74・Zen 4 71)・IOD(122・125)と、既存プリセットの値(Zen 3 CCD 80.7 [二次]・Zen 4 CCD 69.5 [meas]・IOD 117.8 [二次])・Tom's の ISSCC の表(Zen 4 CCD 66.3)が合わない。Zen 5 の CCD 面積は AMD の X3D の製品ページに無い(9700X の既存 70.2 [meas] の流用になる)。**Zen 5 の V-Cache ダイの面積は未取得**。
4. **積層ダイの扱いがモデルに無い**: V-Cache ダイは CCD の上(Zen 3・4)/下(Zen 5)に重なるが、プリセットの dies は横に並べる前提(床面積・熱の計算)。`passive` は「発熱しない土台」用で、L3D(発熱する SRAM)には当てはまらない。dies に入れるなら、面積合計・floorplan・熱で二重に数えない扱い(新しい項目)が要る。入れない(注記だけ)なら変更は不要。
5. **PPT は AMD 公式に無い**([二次] のみ)。5800X3D の PPT は出典未確認。9800X3D の 162W は検索の要約で原ページ未確認(HWCooling は 170W)。
6. **CCD ごとのクロックは AMD 公式に無い**(7950X3D の V-Cache 側 5.25GHz は TechPowerUp の本文 [二次]、9950X3D は未取得)。
7. **全コアクロック**: 7800X3D・9950X3D は未取得(TechPowerUp はグラフだけ)。7950X3D は overclocking.com の値だけで、既存 7950X(KitGuru)と出典が違う。
8. Zen 4 の uarch 記録に L3 遅延(l3Lat)が無い(既定 40)ので、「+4 サイクル」は既定値に足すことになる。
9. GB7 の ST に V-Cache が効くのは小さい(+2〜4%)。ゲームでの効果(数十 %)はこのモデル・この公開値では表せない(対象外)。
10. 9800X3D・9950X3D の DRAM 遅延は 9950X の 70ns の代用 [推定](Chips and Cheese は「通常版とほぼ同じ」と書くが ns の数値は取れなかった)。

## 7. ユーザー判断が要る点

1. 7950X3D をどうするか(§4.3 の perf.js 変更をするか、保留か)。する場合、ST を V-Cache 側(公開値の 58% の投稿)で計算するか。
2. L3 遅延 +4 サイクルを入れるか(入れるなら uarch を分けるか cfg の項目か)。
3. 5800X3D の allCoreGHz 4.4(KitGuru)を入れるか(入れないと MT +11.1% ng)。9800X3D の 5.22(TechPowerUp)を入れるか。
4. ダイ面積に AMD 公式(CCD 71・74、IOD 122・125)を使うか、既存の値に合わせるか。V-Cache ダイを dies に入れるか(入れるなら積層の扱いの設計が要る)。
5. 5800X3D の PPT(peak)を未取得のまま null にするか。

## 8. 実装結果

### 8.1 1 つ目: 1 CCD の 3 件(5800X3D・7800X3D・9800X3D。2026-11-16。perf.js は変更なし)

- ユーザー決定: 5 件(5800X3D・7800X3D・9800X3D・9950X3D・7950X3D)を追加し、7950X3D 用に perf.js へ「CCD 別 L3 と ST の CCD 指定」を入れる。L3 遅延 +4 サイクルは入れない。V-Cache ダイは dies に入れない。5800X3D の allCoreGHz 4.4・9800X3D の 5.22 を入れる(7800X3D・9950X3D は出典が無いので入れない)。5800X3D の PPT は出典未確認なので null。
- 結果(GB7 との差): 5800X3D ST +1.92% / MT +9.01%、7800X3D ST +2.39% / MT +3.60%、9800X3D ST -2.08% / MT +0.42%(すべて ok)。公開値は 2055 / 11814、2460 / 15694、2969 / 18700(§2.4 に追加。四捨五入)。試算(§3.2)との差は公開値の丸めだけ。
- 既存 106 件の評価(再現・改良 212 件)は追加の前後で完全一致。σ・u・連続式の c 0.405 も不変。延べ判定 158 → 164、延べ ng 4 のまま、MAE 3.920 → 3.895%。
- 食い違い・未取得: AMD 公式の CCD 74/71・IOD 125/122 と既存値(80.7・69.5・117.8)の食い違いは既存値に合わせ、note に記録。V-Cache ダイは dies に入れず note に面積(Zen 3 41mm²・Zen 4 36mm² [二次]、Zen 5 未取得)。7800X3D の allCoreGHz・5800X3D の PPT は未取得。9800X3D の PPT 162W は原ページ未確認。
- 変更したファイル・固定値は設計書 §5.3.0【2026-11-16 Ryzen X3D】と §13.4 の行に記録。

### 8.2 2 つ目: 2 CCD の 9950X3D・7950X3D と perf.js の CCD 別 L3・ST の CCD 指定(2026-11-16)

- perf.js に任意項目 `cfg.l3CcdMB`(CCD ごとの L3)・`cores[].ccd`・`cfg.stCcd`(ST の CCD)を追加(§4.3 の最小案どおり。`l3Types` と同じ流儀で、無い SKU は評価が完全に不変)。コア種別名は一意なので 2 つの CCD は種別 P(V-Cache 付き)と P2(通常)。
- 7950X3D: stCcd 0(V-Cache 側。boost 5.25 [二次]・L3 96MB)、allCoreGHz は CCD ごと 4.875 / 5.075(overclocking.com [二次]。平均 4.975)。結果 ST +3.55% / MT +2.31%(+4 サイクルなし。調査メモ §3.3 の「データのみ」と一致)。
- 9950X3D: stCcd 1(通常 CCD。5.7GHz・32MB)。V-Cache 側のクロックは未取得なので P の boost 5.7 は公式最大の暫定値 [推定]、全コアクロックも未取得。結果 ST +0.40% / MT +8.08%(§3.3 と一致)。
- 既存 109 件の評価(218 件)は前後で完全一致。σ・u・c 0.405 不変。延べ判定 164 → 168、延べ ng 4 のまま、MAE 3.895 → 3.888%。
- 非対称の根拠(ST が走る CCD)は GB7 の Maximum Frequency の分布からの読み [推定](§2.4)で、結果ページから直接は確認できない。この点は note・設計書に「確認できない」と明記した。
