# Arrow Lake モバイル(285H・275HX)の MT 過大の切り分け(2026-11-11)

結論: **原因は特定できなかった。係数・データは変更していない**(出典つき実測で特定できたものだけ直す方針)。数値での切り分けを以下にまとめる。

| SKU | 種別 | ST 誤差 | MT 誤差 | MT/ST の残差(= (1+MT 誤差)/(1+ST 誤差) − 1) | W / 係数 | 誤差 0 になる係数 |
|---|---|---|---|---|---|---|
| 285K | デスクトップ | -0.3% | +8.5% | +8.8% | — / 1.000(全コアクロック 5.4 / E 4.6) | — |

## 2. 候補ごとの数値検証

1. **LP-E の扱い(285H)**: 285H の MT のうち LP-E 2 コアは 7.1%。LP-E を 0 にしても +19.7% → +17.6%(約 2 ポイント)で、原因ではない。ほかのモバイル(185H -0.0%、388H -1.6%、268V -4.3%)は LP-E を同じ扱いで合っている。
2. **E コアの寄与(285H・275HX)**: 285H は E が 47%、275HX は E が 61%(E 16 コア)。E を全部外すと -25% / -27% で、E の寄与が全体の合否に効く。ただし 285K(E 61%)は同じ Skymont で +8.5% と近く、E の u の異常を示す証拠はない(`arrow-lake-mt-2026-11-10.md`)。感度: 275HX の E の全コアクロックを 4.36 → 3.8GHz にすると +23.2% → +12.0%、P を 5.12 → 4.5GHz にすると +16.4%。誤差 0 にするには P・E の全コアクロックを一律に約 0.81 倍(P 約 4.2GHz・E 約 3.5GHz)にする必要がある。**ノート PC の全コア負荷時の実測クロック(出典つき)は未取得**なので、クロックを直す根拠は無い。
3. **電力の連続式の外挿(115〜160W)**: 285H(W=115)と 275HX(W=160)は式の係数が 0.903 / 0.948 と違うが、誤差 0 にする係数は 0.754 / 0.749 でほぼ同じ。W に依らず一定の「実効係数 約 0.75」が要る形で、連続式の W 依存では説明できない(`hx-mt-overestimate-2026-11-10.md` §3.6 の「W が同じでも誤差が散る」と整合)。同じ 115W の 185H は係数 0.903 で合っており、285H との差(0.754 対 0.903)は W では説明できない。
4. **ST の偏りが MT に出ている(285H)**: 285H は ST が +11.3%(公開値 2446 が、同じ P の boost 5.4GHz の 275HX の 2607 より低い=ノート PC が 5.4GHz に届かない)で、MT/ST の残差は +7.6% とデスクトップ 285K(+8.8%)・265K(+6.5%)と同じ水準。つまり **285H の MT の過大の大部分は ST の過大(公開値側の偏り。§13.4 ①)で、残りの +7〜9% はデスクトップと共通の過大(γ の縮退の残り。`gamma-smt-2026-11-10.md`)と同じ**。
5. **275HX は別枠**: ST は +5.4% と小さいのに MT/ST の残差が +16.9%(285K の約 2 倍)。ST の偏りでは説明できず、24 コア(P 8・E 16)の全コア負荷での電力・熱の制約(OEM 設定の幅)が疑われる。ノートパソコン研究(`nbc-gb7-mobile.md` §2.2)の GB6 で、275HX の NBC ラボ 30 台の MT は最大 21668(ROG Strix Scar 18、175/150W)から最小 16832(Schenker Key 18 Pro、145/130W)で、最大÷最小 1.29。W が約 17% 小さい機体で 22% 低く、OEM の電力設定による差が大きい([実測] GB6。GB7 ではない)。
6. **メモリ(LPDDR5X / DDR5-5600 の帯域・L3 遅延)**: 285H にはメモリのデータが無く(ARK の取得結果に無い)、メモリ係数は 1(選択肢なし)。275HX の基準構成は DDR5-6400 で 285K と同じ。MT のモデルはメモリ帯域を使っていない(§5.2.2 の BW 頭打ちは未実装)ので、メモリの違いは予測に入っていない。L3 遅延の効果は ±2%(285K の調査で確認済み)。**検証できない候補**。
7. **公開値の電力設定の混在**: 285H の Windows のみ値(150 件)は MT 15750.5 で、OS 混在(15928)と -1.1% しか違わず、Windows のみにしても +21.1% 残る。275HX も Windows のみ(168 件)で +20.9%。OS 混在が原因ではない。電力設定(機体名・電源モード)別の公開値は未取得で、これは分けられていない。

## 3. 結論

- 285H の MT 過大(+19.7%)は、ST の過大(+11.3%)と、デスクトップの Arrow Lake と共通の過大(約 +8%)で説明できる(合成で約 +20%)。**285H 固有の原因は見つからない**。
- 275HX の MT 過大(+23.2%)は、同じ分解で約 +8 ポイント分が説明できず(ST の偏りが小さいため)、24 コアのノート PC の全コア負荷での実効クロックの低下(OEM の電力設定の幅)が疑われるが、**出典つきの実測は無く特定できない**。
- 係数・クロック・η は動かしていない。NG 件数も変わらない。

## 4. 特定に必要な取得(登録のみ)

- 285H・275HX 搭載機の全コア負荷時の P・E の実測クロック(レビューの CPU ストレステスト表など)と、そのときの消費電力。
- Geekbench の電力設定別・機体別の中央値(Geekbench Browser は 403 で未取得)。
- 285H のメモリ構成(ARK)と、メモリ帯域を MT に入れるかの判断(§5.2.2)。
