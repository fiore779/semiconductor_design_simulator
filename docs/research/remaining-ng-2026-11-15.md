## 1. A. Snapdragon 7 Gen 1

### 1.1 原因(既存メモの確認)

`arm-rob-7gen-2026-11-15.md` のとおり、Cortex-A710 は ROB が null なので MLP が上限 10(`mshrDefault`)、ROB のあるコアは ROB ÷ kMlp(48)。7 Gen 1 の IPC は 3.41(ROB 160 を入れると 2.53)。

### 1.2 kMlp の掃引(uCal と c を取り直したうえで全 158 判定)

| kMlp | A710 ROB | 延べ ng | c(取り直し) | σ | A78 uCal の倍率 | 7 Gen 1 ST / MT | 8 Gen 1 / 8+ Gen 1 / 9000 の MT | 新たに ng になる主なもの |
|---|---|---|---|---|---|---|---|---|
| 24 | null | 13 | 0.446 | 0.0365 | 0.805 | +6.3 / +11.4 | — / -13.1 / -17.5 | 5800X・5600X・7735HS・1200 の MT など |
| 24 | 160 | 13 | 0.446 | 0.0365 | 0.805 | -2.2 / +4.0 | -11.4 / -17.6 / -21.7 | 同上 |
| 32 | null | 10 | 0.430 | 0.0351 | 0.870 | +8.9 / +15.0 | — / -11.1 / -15.5 | 5600X MT、8 Elite Gen 5 MT |
| 32 | 160 | 10 | 0.430 | 0.0351 | 0.870 | -7.3 / +0.8 | -13.4 / -19.5 / -23.5 | 同上 |
| **48(現状)** | null | **8** | 0.405 | 0.0315 | 1 | +17.5 / +26.6 | +2.2 / -4.7 / -9.2 | — |
| 48 | 160 | 10 | 0.405 | 0.0315 | 1 | -12.9 / -0.6 | -14.6 / -20.8 / -24.6 | 8 Gen 1 系 3 件 |

| 96 | null | 23 | 0.383 | 0.0231 | 1.391 | +47 / +66 | — | 多数 |

(mobile の MT 係数は 0.91 のまま。Cougar Cove・Redwood Cove は ROB null なので uCal の倍率は 1。)

読み取り:
- kMlp は x86 を含む全 uarch の u・σ・c を動かし、48 から離れるほど ng が増える。**48 が掃引の中で最少**。
- **A710 に ROB 160 を入れると、どの kMlp でも 8 Gen 1・8+ Gen 1・9000 の MT が ng**(-11〜-25%)。A710 と A78 は ROB が同じなので kMlp では両者の差が変わらず、差の元は基本 CPI(1/幅: 1/5 対 1/6)と L2 遅延(13.5 対 9)。
- A710 に `uRatioOf: 'Cortex-A78'` を付けて u を持ち上げても(`expA2.js`)、比 1.12 で 7 Gen 1 ST -2.8 / MT +8.7、8 Gen 1 MT -9.3 だが、**8+ Gen 1 -15.9・9000 -19.7 が ng のまま**(比 1.15 で 7 Gen 1 MT が ng に戻る)。そもそも比を決める A710 を P コアに持つ SKU は 7 Gen 1 だけで、7 Gen 1 自身から決めると循環。

### 1.3 kMlp を独立に決められるか

- Arm の TRM・SOG の L1D の outstanding miss 数(linefill buffer)は、Cortex-A78 の TRM の目次(A6.4 L1 data memory system。https://documentation-service.arm.com/static/5f159b6720b7cf4bc5247448 )までは見えたが、本文の数値は**未確認**。Chips and Cheese の A725 の記事(https://old.chipsandcheese.com/?p=37766 )にも MLP・outstanding miss の数値は無い(取得 2026-11-15)。
- 仮に取れても、それは「ハードが同時に抱えられるミスの最大数」(通常 20 前後〜数十)で、モデルの MLP(実効の平均並列度。A78 で 3.3、X2 で 6.0)とは**別の量**。kMlp = ROB ÷ MLP は「ROB 何エントリあたりミス 1 個が重なるか」という校正前の形の係数で、ハードの数から一意には出ない。
- 結論: **kMlp は独立の根拠で決められない → 根拠なしで動かさない**。ROB null の扱いを変える案(例: null のときに代わりの ROB を仮定する)も推測値を入れることになるので採らない。7 Gen 1 は「直せない(モデル構造: 基本 CPI = 1/幅 が A710 を過小にする)」。

### 4.2 計算 [推定]

- R23 の MT/ST: 7840HS 16155.5 ÷ 1775 = 9.10、7700X 19088 ÷ 1987 = 9.61 → 比 **0.947**。GB7 の公開値の比(7840HS 5.61 ÷ 7700 6.15)は 0.912。**モデルは 4.61 ÷ 6.05 = 0.762** で、2 つの独立なベンチマークの両方より大幅に低い。
- 全コアクロック ≈ 7700X の R23 全コア 5.2GHz × R23 マルチの比(16155.5 ÷ 19088 = 0.846)= **4.40GHz**(同じ Zen 4・8C16T で、R23 の 1 クロックあたりの MT 性能が同じと仮定。L3 16MB 対 32MB の差は R23 では小さいと仮定 [推定])。
- 連続式(54W で係数 0.737 → 3.76GHz)は Phoenix を約 15% 低く見積もっている。7840HS の必要クロックは約 4.18GHz(係数 0.82)。

- 7840HS は連続式の c の標本から除外済み(tests/perf.test.js)なので c は不変(0.4046)。ST は変わらない(+8.8%)。
- 前例(5950X 3.925・7950X 5.0・285K 5.4・265K 5.2・12100 4.1)はすべて `kind: 'pc'` の直接の実測。今回は ①**直接の測定ではなく 2 つの資料からの導出値 [推定]**、②**mobile-pc で初めての allCoreGHz**。mtScore は allCoreGHz があると係数を掛けないので、TDP の選択(35〜54W)や冷却クラス(coolingW)が 7840HS の MT に効かなくなる。実装するなら「allCoreGHz は range.maxW(54W)での値とし、選んだ W では連続式の比 (W/54)^0.15 を掛ける」等の扱いを設計書で決める必要がある(ユーザー確認)。
- 公開値に合わせて選んだ値ではない(GB7 の 7840HS の公開値は使っていない)。R23 の値は 7840HS 搭載機の集計で、母集団は GB7 と別。

### 6.1 前提(既存の [実測]。5800u-st-cause-2026-11-14.md)

### 6.3 前例との整合と、根拠の強さ・弱さ

- 前例: ST のクロックは全 SKU で公式の boost(Intel は ARK の P コア最大ターボ)。7950X 等の allCoreGHz は **MT だけ**の実測値で、ST の定義は変えていない。Zen 3+ の u × 0.95 は Maximum Frequency(動作クロック基準)で**比を決めた**が、評価は boost のまま。つまり「評価のクロックを Maximum Frequency にする」前例は**無い**。
- 強い点: 4.064GHz は [実測](76 件全件の結果ページ)。公開値の定義(Windows 投稿の中央値)を変えずに、同じ投稿の母集団のクロックにモデルを合わせるので、母集団の差(B)をそのまま説明する。5800U の公開値に合わせた係数ではない。
- 弱い点: ①5800U だけに当てると、ST のクロックの定義が SKU ごとに割れる(Zen 3 の代表 5800X は公称 4.7 に対し Maximum Frequency 4.84GHz で、同じ扱いにすると Zen 3 の u が約 3% 下がり、Cezanne・Zen 3+ の比も取り直しになる)。②全 SKU に広げるには AMD・Arm の全 SKU の Maximum Frequency の集計が要り、Intel は数十機種で一定の申告値なので使えない(ipc-clock-ng-2026-11-15.md §3)。③Maximum Frequency の取得方法は Geekbench の公式文書で未確認で、「最大」であって持続クロックではない。④4.064 は 1 機種(HP ProBook x360 435 G8、20 件すべて 4064MHz)の影響が大きい。
- → **ユーザー判断**(公開値の定義の問題として扱う。5800U だけに入れる場合は、上の①〜④を errCause と設計書に明記する)。

## 7. 推奨と分類

| 区分 | 項目 | 理由 |
|---|---|---|
| 推奨(ユーザー確認 1 点) | **D: 7840HS の P に allCoreGHz 4.40** | 独立の 2 資料(NBC R23 [実測]・KitGuru [二次])からの導出 [推定]。循環なし。ok→ng なし。確認点は mobile-pc で allCoreGHz を使う扱い(TDP 選択・冷却が効かなくなる)と、直接の実測ではないこと |
| ユーザー判断 | E: 14700HX の典型電力(R23 の比で W ≈ 69W 相当) | 根拠は独立(NBC R23)だが、SKU 1 件だけ電力の規則から外れる |
| ユーザー判断 | F: 5800U の典型動作クロック 4.064GHz | 根拠は [実測] だが、ST のクロックの定義を SKU ごとに変えることになる |
| 直せない | A: 7 Gen 1 | kMlp は独立に決められない(48 が最少)。A710 の ROB 160 はどの kMlp でも 8 Gen 1 系を ng にする。原因はモデル構造(基本 CPI = 1/幅) |

## 8. 限界

1. D の 4.40GHz は、R23 の「1 クロックあたりの MT 性能が 7840HS と 7700X で同じ」という仮定の上の導出値で、直接の全コアクロックの実測ではない(4.0〜4.65GHz のどれでも MT は ok)。R23 と GB7 の MT は負荷の性質が違う(GB7 はメモリの影響が大きく、実行が短い)。
2. NBC の集計は機種ごとの n と内訳を今回読んでいない(中央値・平均・最小・最大のみ)。NBC の測定機は GB7 の投稿機と別の母集団。
3. E の 0.818 は 14900HX を基準にした相対値で、14900HX 側の誤差(+2.5%)をそのまま引き継ぐ。
4. kMlp の掃引の uCal の取り直しは「標本の補正前予測の変化率の中央値」で既存の u をスケールした近似(Redwood Cove の参考 SKU は計算していないが、ROB null で kMlp の影響を受けない)。mobile の MT 係数は 0.91 のまま(逆算し直した値は表の注記のみ)。
5. A715 の ROB は「192+」の下限のまま。A710・A715 の Arm の原資料、7 Gen 1・9200 の L2・L3・SLC は未取得。
6. 888・9200 の通常の群の定義(P95 × 0.8)は既存の実装上の判断。9200 は通常の群が 45 / 200 件と少ない。
7. Arm の TRM の outstanding miss 数は目次までで本文は未確認。

## 10. 実装結果(2026-11-15。ユーザー決定「7840HS は allCoreGHz 4.40 を [推定] と明記して入れる。14700HX は typicalW 項目を追加して直す」)

### 10.1 D: 7840HS の MT(1 つ目のコミット)

- 実装: `data/presets/chips-pc.js` の 7840HS の P に `allCoreGHz: 4.40`([推定]。導出と仮定は notes・errCause.mt に記載)。errCause.mt の古い記述(c の再校正で -10.5% の ng)に現状を追記。
- 結果(全 106 プリセットの前後比較): 7840HS の MT **-10.54% → +1.39%**(ng → ok)。ST は +8.82% のまま。**延べ ng 8 → 7**(ok → ng 0 件)。**ほかの SKU の ST・MT は完全一致**。σ 0.03151・連続式の c 0.4046(丸め 0.405)も不変(7840HS は c の標本 11 件に入っていないので、allCoreGHz は標本の k_i に効かない)。
- 効かなくなる範囲(コードで確認): `mtScore` は allCoreGHz のあるコアに係数を掛けないので、7840HS の MT は選んだ TDP(35W)にも冷却クラス(laptop-thin-light 28W)にも効かない(試算で MT は 12619.6 のまま。allCoreGHz なしでは TDP 35W で下がる)。ST・電力・温度・面積は不変。
- 追加の実装(逸脱として報告): ①`mtClockInfo` に `powerIgnored`(全コアが allCoreGHz を持つ mobile-pc だけ)、②`evaluate` の `coolLimited` を `powerIgnored` のとき偽に(MT が変わらないのに「冷却で制限」「編集済み」にしないため。TDP 選択の「編集済み」は従来どおり)、③`evaluate.allCoreInfo` と結果パネルの MT の注記・`calibrationWarnings` の info。デスクトップの allCoreGHz には出さない。

### 10.2 E: 14700HX の MT(2 つ目のコミット)

- 実装: プリセットの `power` に任意項目 `typicalW`(数。W)と `typicalNote` を追加し、14700HX に `typicalW: 69`([推定・校正値])。`mtPublishedW` の優先順位を「選んだ TDP > typicalW > range.maxW > base」とし、冷却の制限(min)はそのまま効く。`evaluate` の `tdpNonDefault` の既定値を typicalW(あれば)に。結果パネルの MT の係数の注記に「典型電力 typicalW」を出す。`tools/validate-data.js` に検査を追加。typicalW は保存データに載らない(プリセット由来のみ)。
- 値の決め方: NBC の R23 マルチの比 14700HX ÷ 14900HX = 0.818 をモデルが再現する W = 68.9W → 69W。GB7 の比 0.824(約 72W)は追認。14700HX の公開値には合わせていない。
- 結果(全 106 プリセットの前後比較): 14700HX の MT **+12.83% → +1.80%**(ng → ok)。ST は +4.47% のまま。**延べ ng 7 → 6**(7840HS と合わせて 8 → 6)。ほかの SKU の ST・MT は完全一致、電力・温度・面積も 14700HX を含め不変。連続式の c は 0.4046(丸め 0.405)で不変: 標本 11 件に 14700HX は入っており、k_i ÷ W_i^0.15 が 0.3505 → 0.3965 に動くが、中央値の下のまま。標本内 MAE 0.0600 → 0.0500、LOO MAE 0.0660 → 0.0559、一律 0.81 は 0.0768 のまま。
- 試算(W → 14700HX MT): 157W +12.8%、100W +6.7%、80W +3.7%、69W +1.8%、55W -1.1%。調査メモ §5.2 の +1.7%(68.9W)は、69W で +1.80%。
- 残る ng(ユーザー決定のとおり変えない): 5800U の ST・MT、7 Gen 1 の ST・MT、9200 の MT、888 の MT(合計 6 件)。
