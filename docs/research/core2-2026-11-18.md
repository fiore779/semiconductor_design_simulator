# Core 2 世代(Wolfdale・Yorkfield)を追加(2026-11-18)

ユーザー指示「core2も追加してください。情報収集もしていないので情報取得からになると思います」。`data/presets/chips-old.js` に 3 SKU を追加した(136 → 139 件)。

## 1. SKU の選び方

Geekbench Browser v7 検索(q=型番)の Windows の投稿のうち、SKU 名が完全一致のもの(取得 2026-11-18。全件 200 未満)。

| SKU | ダイ | Windows 標本 | 採否 |
|---|---|---|---|
| E8400(2C、3.0GHz) | Wolfdale 6M | 13 | 採用 |
| Q9550(4C、2.83GHz) | Yorkfield(Wolfdale ×2) | 14 | 採用 |
| Q9650(4C、3.0GHz) | Yorkfield | 13 | 採用 |
| Q9400 | Yorkfield-6M | 8 | 見送り(標本が少ない) |
| E8600 6・E7500 5・E7300 2・E7200 3・E8500 1 | Wolfdale | 6 以下 | 見送り |
| Q6600 4・Q6700 1・Q9300 1・E6600 1・E6850 1・E6550 3 | **Conroe・Kentsfield(65nm)** | 4 以下 | 見送り(標本が少ない) |

**65nm の Core 2(Conroe・Kentsfield)は Geekbench 7 の Windows の標本が 4 件以下で、1 つも入れていない**。Core 2 の uarch「Penryn」は 45nm 版(Wolfdale・Yorkfield)で、65nm 版の uCal の標本ではない。

標本にはオーバークロックが含まれる(E8400 は 13 件中 3 件、Q9550 は 14 件中 5 件、Q9650 は 13 件中 4 件。動作クロックが定格の +5% を超えるもの)。プロジェクトの標準(Windows のみの全件の中央値)に合わせ、除外せずに中央値を採った。定格だけの中央値は E8400 442 / 690.5、Q9550 416 / 1171、Q9650 449 / 1321(参考。設計書 §2.4 の備考にも記載)。

公開値(設計書 §2.4): E8400 444 / 743、Q9550 425 / 1255(424.5 を四捨五入)、Q9650 455 / 1334。

## 2. 構成・ダイ・電力

- **ダイ面積**: Wolfdale 2C は 107mm²([公表]。Intel の 2007-03-28 の Penryn 資料 https://www.intel.com/pressroom/archive/releases/2007/20070328fact.htm「デュアルコアは 107mm²」。Wikipedia の Core 2 一覧も同じ)。Yorkfield は 107mm² のダイ 2 つの MCM で、モデルでは 214mm² の 1 つのダイ([二次]。Wikipedia「2 × 107 mm²」、Tom's Hardware は 214mm²。Zen の「CCD ×2」と同じ書き方)。
- **キャッシュ**: L2 は 2 コアで共有する 6MB(Yorkfield は各ダイ 6MB ×2、合計 12MB)。**L3 はない**ので `cfg.l3MB` は 0(評価は noL3 の経路)。メモリコントローラはチップセット側で、FSB 1333MT/s(プリセットのメモリ欄は FSB と板の違いを書いた)。
- **クロック**: ターボなし・HT なし。E8400 3.0GHz・Q9550 2.83GHz・Q9650 3.0GHz。全コアクロックは基本と同じなので allCoreGHz は設定しない。
- **TDP**: E8400 65W は Intel ARK の記載(検索で得た要約。古い SKU の ARK ページ本体は取得できない)。Intel の Quick Reference Guide(2008)も 3GHz・45nm・6MB・1333MT/s で一致。Q9550・Q9650 の 95W は Wikipedia の Core 2 一覧(Q9550S は 65W の別 SKU)。すべて [二次]。
- 発売: E8400 2008-01、Q9550 2008-03、Q9650 2008-08(Wikipedia)。

## 3. uarch「Penryn」(`data/uarch.js`)

| 項目 | 値 | 出典 |
|---|---|---|
| 幅・デコード | 4 | Agner Fog の microarchitecture.pdf 8.2(パイプライン全体の通常のスループットは 1 クロック 4 命令) |
| ROB | 96 | 同 8.1。Chips and Cheese の Penryn の記事も 96 |
| 分岐ミスの罰則 | 15 | 同 8.1(「少なくとも 15」) |
| L1D 遅延 | 3 サイクル | Chips and Cheese(Penryn の記事) |
| L2 遅延 | 約 15 サイクル | 同(Merom より 1 サイクル遅い) |
| L2 容量 | 3MB/コア | 6MB 共有 ÷ 2 コアの近似(共有の競合は考えない) |
| SMT・ベクトル | なし・128bit | SSE4.1 まで |

L3 遅延・MSHR は存在しない・未取得。Penryn の L2 遅延は Wolfdale・Yorkfield 個別の実測ではない。

ST の補正 u(uCal)は SKU 別 u の中央値 **85.7**(E8400 85.7・Q9550 85.4・Q9650 87.8。n=3)。学習内で、検証ではない。3 SKU のばらつきは小さい(2 コアのダイと 4 コアの MCM で整合)。

## 4. 再現度(公開値との差。学習内)

| SKU | ST 誤差 | MT 誤差 |
|---|---|---|
| E8400 | 0.0% | **+15.8%** |
| Q9550 | +0.3% | **+24.2%** |
| Q9650 | -2.4% | **+21.6%** |

**ST は ±10% 以内だが、MT は 3 件とも許容(±10%)を超えて高く出る**。専用の係数は入れていない(ユーザー方針)。

- 公開値の実効スケーリングは、2 コアで 1.67 倍(E8400。定格だけだと 1.56 倍)、4 コアで 2.95 倍(Q9550)・2.93 倍(Q9650)。モデルは σ = 0.0315(AMD の代表から校正)の共通の並列効率で、2 コア 0.97・4 コア 0.91 を与えるため、実際の約 0.84(2 コア)・約 0.74(4 コア)より高い。
- 考えられる原因(**未検証**。出典のある実測ではない): Core 2 はメモリコントローラがチップセット側で、全コアが 1 本の FSB(1333MT/s ≒ 10.7GB/s)を共有する。モデルには「プラットフォームの帯域の頭打ち」が MT に入っていない。また、共有 L2 は 1 コアだと 6MB を独り占めできるのに、モデルは 3MB/コアで固定。ハイパースレッディングなしの MT が過大になる傾向(i5-3570K・i5-8400。docs/research/old-intel-mt-ng-2026-11-17.md)の延長の可能性もある。
- i5-8400 は同様の MT +18.2% を原因不明としてユーザー判断で外した(2026-11-17)。Core 2 は新しい世代の追加指示なので、外さずに入れ、MT が許容を超えることをここと設計書に記録した。

## 6. 限界

- MT が許容(±10%)を超える(上記)。
- 65nm の Core 2(Conroe・Kentsfield)・Q9400 などは標本不足で未収録。
- TDP・構成は Intel ARK の本体を取得できず [二次]。
- Yorkfield の 214mm² は 107mm² の 2 倍(ダイ間の隙間・パッケージは含まない)。
- 共有 L2 の容量近似(3MB/コア)と FSB の帯域はモデル化していない。
