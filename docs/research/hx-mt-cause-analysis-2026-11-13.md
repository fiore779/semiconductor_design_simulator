# HX / Arrow Lake モバイルの MT 過大: 原因の分解と仮説の定量検証(2026-11-13)

- 対象コミット: 6cd207f(PC 系 CPU の GB7 公開値を Windows のみの中央値に差し替え、再校正した後)。σ=0.03306、γ=0.30、連続式 c=0.411・指数 0.15、Lion Cove u=102.13、Raptor/Golden Cove uCal=116.5、x86 ISA 平均 u=109.18。
- 方法: `tests/helpers.js` と同じ読み込みで `E.makeContext()` を作り、全プリセットを `evaluate`(reproduce)で評価。仮説は `perf.mtScore` / `stScore` に渡す値(W、係数、u)だけを差し替えて試算した。**コード・データ・設計書は変更していない(試算のみ)**。使い捨てスクリプトはセッションの scratchpad(`base.js`・`hyp.js`・`s1.js`〜`s8.js`)。
- データ区分: GB7 公開値 = **[実測]**(Geekbench Browser の Windows 投稿の中央値、`gb7-windows-only-2026-11-13.md`)。冷却クラスの sustainedW と NBC の機体別 PL1 = **[実測]**(Notebookcheck。PL1 はスペック欄の設定値、`cooling-class-power-2026-11-12.md` §2・§4-1)。予測値・k・等価電力・試算の誤差 = **[推定](モデル計算)**。因果の解釈は **[推測]** と明記した。
- 「確認済み」は本解析で数値として再計算・照合したもの。「推測」は数値から読んだ解釈で、出典つきの実測で裏づけていないもの。

## 0. 結論(要約)

1. **ユーザー仮説(冷却で持続電力が下がる)は、現行の連続式(指数 0.15)のままでは HX の過大をほとんど説明しない**(確認済み)。HX を大型ゲーミング 145W に制限しても MT 誤差は -1.0〜-1.4 ポイント、ゲーミング標準 125W でも -3.3〜-3.6 ポイント。誤差 0 になる等価電力は 14700HX 48W・275HX 50W・285H 34W で、実測の持続電力(NBC の PL1 中央値 95・130・74W、クラス中央値 125〜145W)の **0.4〜0.5 倍**。±10% に入れるだけでも 102.6W・105.9W・70.5W まで下げる必要がある。
2. **最も説明力が高いのは、SKU ごとに違う 2 つの要因**(分解は確認済み、因果は推測):
   - **275HX(と 285H の一部)= Arrow Lake 共通の MT 過大**。デスクトップの 285K 自体が MT +10.8%(ng)で、275HX の誤差 +15.9% のうち約 +10.8 ポイントは 285K と同じ過大の引き継ぎ。原因候補は Skymont(E コア)の u が x86 ISA 平均の 109.18 を借りていること。285K・265K の MT から逆算すると 91.7・99.8 になる。
   - **14700HX・285H = モバイル ST の不足がそのまま MT に乗っている**。ST 誤差はそれぞれ +11.1%・+16.8%。デスクトップの兄弟と比べた ST の不足は 14700HX +12.7%、285H +14.4%。これを除いた MT の残差は 14700HX で +0.8%、つまり MT の電力係数 0.8775 自体は 14700K と比べて整合している。
3. **14900HX(ok)と 14700HX(ng)の差(公開 MT の比 1.214 に対し予測は 1.096、差 10.7%)**は、次の 3 つにほぼ等分される: デスクトップでも同じ方向にずれている分 3.7%、ST の不足の差 2.9%、残り 3.7%。残りは搭載機の電力分布(NBC の PL1 中央値 130W 対 95W。指数 0.15 で 4.8% 相当)で説明できる大きさ(推測)。件数(両方 n=200)、コア数表示の混入(フルコア表示のみの中央値と一致)、VM 投稿の影響は 0。
4. **285H の ST +16.8% は MT とは別の要因**。モデルの ST は 275HX と L3 の差の -0.9% しか違わないのに、公開値は 0.918 倍。モバイル H/U の ST の過大の中央値は +10.0% で、285H はさらに +6〜7 ポイント外れている。加えて Lion Cove の u が 265K の取り直しで +3.9% 動いた分(旧 u 98.32 なら 285H の ST は +12.5%)。
5. **推奨(実装はしない)**: ① Skymont の u をリング接続の E コアだけデスクトップ Arrow Lake の MT から決める(LP-E は ISA 平均のまま)。試算は ng 33 → 31(285K・275HX が ok に)、ok→ng は 0 件。② 冷却の既定は「クラス一律」ではなく、SKU ごとの搭載機の分布(PL1 中央値)にする方向。ただしこれは出典つきの機体別 GB7 を取ってから(試算では 14700HX・285H・7840HS が改善する一方、258V などが ok→ng)。③ モバイルの ST の不足は MT とは別の課題として扱う(参考試算: mobile-pc の ST だけに一律 0.90 を掛けると ST の ng 11 件が ok、MT は不変)。

## 2. 検証(1): 冷却の既定クラスと、実測の持続電力・等価電力の乖離

### 2.1 既定の冷却(確認済み)

- mobile-pc の既定の冷却は `thin-laptop`(`js/model/design.js` の DEFAULT_COOLING)。これは sustainedW を持たない仮置きの冷却なので、**既定では冷却による MT の制限は掛からない**。MT の W は全 SKU で公表の MTP(range.maxW)。「HX は大型ゲーミング 145W」という既定は現在の実装には無く、ユーザーが選んだときだけ効く。

## 8. 推奨する修正案(実装はしない。ユーザー判断)

1. **(最優先・データ/係数)Skymont の u を、リング接続の E コアだけデスクトップ Arrow Lake の MT から決める**(例: `uarch.js` に uCal を持つ「Skymont(Arrow Lake のリング接続)」を分ける。LP-E と Lunar Lake の E は ISA 平均のまま)。
   - 試算: ng 33 → 31(285K と 275HX が ng→ok)、ok→ng 0 件、x86 モバイルの MT MAE 7.14 → 6.44。値は 95.77(285K・265K の中央値)でも 99.84(265K のみ)でも ng は 31。
   - 注意: 標本は 2 件で、u と η・σ を分離できない(MT から逆算した「E の u」は ST の u とは意味が違う)。Lunar Lake は Skymont 全体に当てると -10.6〜-14.7% に崩れる。LNL はもともと MT が過小(MT/ST 残差 -16%)で、37W の係数が低すぎるという別の問題を抱えている。このため LP-E は分けて扱う必要がある。当て込みになる危険はある(推測)。
   - 先に取るべき出典: Skymont 単体の性能比(Chips and Cheese の IPC 比較など)。
2. **(データ待ち)冷却の既定を SKU ごとの搭載機の分布にする**。クラス一律(HX → 145W)では効かない(§2.3)。PL1 中央値を SKU の既定の持続電力にして c を再校正すると(H1d)、1 と合わせて ng 30(285H・7840HS も ok)。ただし 258V が ok→ng になり、388H も -9.1% と境界に寄る。
   - 根拠が弱い: PL1 中央値は NBC の CPU ページの先頭の範囲だけで、件数は 7〜27。GB7 の投稿の機体の分布とは別物。
   - 先に `hx-cooling-limit-2026-11-12.md` §6 の (a)(Geekbench Browser の機体名別の MT 中央値)を取って、「公開値の機体がどの電力クラスか」を確かめるのが条件。14700HX はこれが無いと直せない(1 だけでは +16.0% のまま)。
3. **(別課題)モバイルの ST の不足を、MT とは別のモデル項として扱うか判断する**(mobile-pc の ST だけの係数。試算 0.90 で ST の ng 33 → 22、MT は不変、ok→ng なし)。値は [推定・校正値] で、物理的な根拠(ST の boost を保てないこと)は推測。285H の ST(+16.8%)の主因はこれと、Lion Cove の u が 265K の取り直しで動いた分。
4. **採らない方がよい案**: HX だけ W を PBP やクラス値に下げる(HX 間の差を作れず、H/U 系も同時に崩れる)。同一 SKU 内の強い指数(q≥0.3)を SKU 間に使う(388H・395・185H・LNL が ok→ng)。Gracemont の u を一律に決める(Raptor のデスクトップ間で逆算値が 91〜139 に散る)。指数の引き上げ(PL1 の W では 0.15 が最良で、0.3 で ng 38)。
