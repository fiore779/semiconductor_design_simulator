# 残りの ng(285H・14700HX・7840HS)をスコアと動作クロックから見直す(2026-11-15・調査と試算だけ)

ユーザー指示「ng の残りを、スコアと動作クロックから IPC を取得して直す」。今回は**調査と試算だけ**で、コード・データ・設計書は変えていない(実装は別担当)。
手本: `docs/research/zen3plus-ipc-2026-11-15.md` とコミット 70c4fb1(7735HS の u × 0.95)。

区分: [実測] = Geekbench Browser v7 の Windows 投稿を自分で集計した値(2026-11-15 取得)、[公表] = Intel ARK、[推定・校正値] = そこから出した u の比。

対象の ng(誤差 = (モデル − 公開値) ÷ 公開値。公開値は Windows のみの中央値。設計書 §2.4):

| SKU | ST | MT |
|---|---|---|
| Core Ultra 9 285H | **+11.49%** | +7.82% |
| Core i7-14700HX | **+11.14%** | **+17.14%** |
| Ryzen 7 7840HS | +8.82% | **−10.54%** |

## 0. 結論

| SKU | 判定 | 推奨 | 補正後の誤差(試算) | 根拠の強さ |
|---|---|---|---|---|
| 285H | **ST は補正できる** | uarch 記録「Lion Cove (Arrow Lake-H)」= Lion Cove の u × **0.92**(285H だけが使う) | ST +11.49 → **+2.57%**、MT +7.82 → **+3.52%**(どちらも ok) | 中。比は主に別 SKU の 255H から(285H 自身の値は循環に近いので追認だけ) |
| 14700HX | **ST は補正できる。MT は直らない** | uarch 記録「Raptor Cove (HX)」= Raptor Cove の u × **0.94**(14700HX・14900HX・13980HX の 3 件が使う) | 14700HX: ST +11.14 → **+4.47%**(ok)、MT +17.14 → **+12.83%(ng のまま)**。14900HX ST +8.18 → +1.69%、MT +5.98 → +2.52%。13980HX ST +6.98 → +0.56%、MT +5.63 → +2.19% | 中〜弱。比は兄弟の 14900HX・13980HX から(14700HX の公開値ではない)。ただし Intel の Maximum Frequency は動作クロックではない(§3) |
| 7840HS | **u では直せない(やらない方がよい)** | 変更なしを推奨 | ST の u 補正(× 0.95 前後)は ST を +3〜4% に下げるが、ng の MT が −10.5% → **−14〜−15%** に悪化する | ST の比は取れた(7840HS・8845HS)が、ng の原因は MT 固有 |

- 推奨セットは「285H × 0.92」と「HX 3 件 × 0.94」の 2 つ(どちらも新しい uarch 記録 + `uRatioOf`)。両方入れると延べ ng は 7 → **6**(285H が ok になる。14700HX は MT が残る)。ほかのプリセットは ST・MT・誤差とも完全に一致(js で全プリセットを再評価して確認。§5)。
- 連続式の c(0.405。標本 11 件の k_i ÷ W_i^0.15 の中央値 0.4046)は**どの案でも不変**。14700HX は標本に入っているが、k_i は 0.3354 → 0.3505 で中央値(0.4046)より下のまま。
- 7840HS の MT(−10.5%)と 14700HX の MT の残り(+12.8%)は MT 固有の原因で、ST の IPC からは直せない(§6)。

## 1. 取得の手順(2026-11-15)

手本(7735HS)と同じ。

1. Chrome(Claude in Chrome)で https://browser.geekbench.com/v7/cpu/search?q=<SKU 名> を開き、そのページ上で `fetch('/v7/cpu/search?q=...&page=N')`(N = 1〜8。最大 200 件)を DOMParser で解析。行は `.list-col-inner`、スコアは `.list-col-text-score`(ST・MT の順)、OS は行テキストの `Platform` の次の語。
2. Platform が Windows で、モデル名がその SKU に一致する行だけを残す(例: 7700 は 7700X を除く正規表現)。
3. 各結果ページ(`/v7/cpu/<id>`)を fetch し、`Maximum Frequency ... NNNN MHz` を正規表現で取る(10 件ずつ並列)。
4. しきい値: AMD は 4000MHz 以上(手本と同じ。低クロックの投稿を除く)。Intel は全投稿の Maximum Frequency が 5000MHz 以上で、ほぼ一定値(§3)なので、しきい値 5000MHz(実質すべて)。
5. 「ST ÷ Maximum Frequency(GHz)」(点/GHz)の中央値、ST・MT・クロックの中央値、機種数(System 名のユニーク数)を出す。

## 3. Intel の Maximum Frequency は動作クロックではない(重要な限界)

- AMD(7840HS・8845HS・7700・7945HX)は投稿ごとに値が散らばり、電源設定の低い投稿は 2400MHz 台になる。手本(7735HS・5800X)と同じく、ある程度は動作に近い値。
- Intel のモバイル(285H・255H・14700HX・14900HX・13980HX・275HX)は、数十機種でほぼ**同じ値**(285H 5386、255H 5087、14700HX 5287)。デスクトップも 5500・5600・5699・6000 などの段に固まる。計測した値ではなく、プラットフォームが申告する定格(のようなもの)と見られる。
- Intel ARK [公表](2026-11-15 に Chrome で確認):
  - 14700HX(https://www.intel.com/content/www/us/en/products/sku/235997/intel-core-i7-processor-14700hx-33m-cache-up-to-5-50-ghz/specifications.html ): Max Turbo 5.5 GHz、P コア最大ターボ 5.5 GHz、Turbo Boost Max 3.0 5.4 GHz。GB の値 5287MHz はどれとも一致しない(約 0.21GHz 低い)。
  - 14900HX(https://www.intel.com/content/www/us/en/products/sku/235995/intel-core-i9-processor-14900hx-36m-cache-up-to-5-80-ghz/specifications.html ): Max Turbo 5.8 GHz、P コア最大ターボ 5.8 GHz、Turbo Boost Max 3.0 5.7 GHz。GB は 5586(115 件)/ 5785(23 件)。
  - GB の値が ARK と 0.2GHz ずれる理由は未確認(申告値の出どころは不明)。**プリセットのクロックを GB の値に変える根拠にはならない**(公式の 5.5GHz と食い違うので推奨しない)。
- このため、Intel の「点/GHz」は実質「ST 中央値 ÷ ほぼ一定の値」で、**動作クロックの違いと IPC の違いを分けられない**。とくに 285H は Max Freq が 1 つの値に固まっているので、285H 自身の点/GHz から出す比は「285H の ST 中央値に合わせる」のとほぼ同じ(循環に近い)。だから 285H の比は兄弟の 255H から取り、285H 自身は追認だけにした。

## 4. 計算

モデルの点/GHz は ST 予測 ÷ プリセットの boost(fGHz)。モデルの点/GHz はクロックにほぼ依存しない(285K は 5.5GHz で 519.35、5.699GHz で 518.42。差 0.2%)ので、GB の Max Freq で計算しても比はほぼ同じ。

u の比 = (対象の実測の点/GHz ÷ モデルの点/GHz) ÷ (基準の実測 ÷ 基準のモデル)。基準の「実測 ÷ モデル」を m とする。

## 6. MT の誤差の分解(ST の u で動く分と MT 固有の分)

MT のクロックは mobile-pc の連続式 min(1, 0.405 · W^0.15)(W = range.maxW)× boost。7840HS は W = 54 → 係数 0.737(P 全コア 3.76GHz)、14700HX は W = 157 → 0.865(4.76GHz)、285H は W = 115 → 0.825。

### 6.1 14700HX(MT +17.14%)

- MT/ST の比: 実測 15395 ÷ 2362 = 6.52、14700K は 20064 ÷ 2663 = 7.53(HX ÷ K = 0.865)。モデルは 6.87 と 7.97(0.862)。**MT/ST の比はモデルと実測でほぼ同じ**で、MT の過大の大半は ST の過大(+11.1%)がそのまま乗った分。
- ただし u の補正は P コアにしか効かない(E の Gracemont は別の u)ので、ST を +4.5% まで下げても MT は +12.8% に残る(P が MT に占める割合のぶんしか下がらない)。
- 兄弟との比較: 同じ 157W の 14900HX・13980HX は補正後 MT +2.5%・+2.2% で合う。14700HX だけ MT が低い(実測 MT 14700HX ÷ 14900HX = 0.824、モデルは 0.911)。投稿機の電力設定(中級のゲーミングノートで PL が低い、など)の疑いがあるが未確認。連続式で 14700HX の必要係数を W に換算すると約 60W 相当。
- 結論: MT の残り約 +8 ポイント分は MT 固有(14700HX の投稿機の電力・冷却)で、IPC では直せない。冷却の選択(laptop-gaming 125W など)で W を変えれば下がるが、W を公開値に合わせて選ぶ根拠は無い(推測値になるので推奨しない)。

### 6.2 7840HS(MT −10.54%)

- MT/ST の比: 実測 12446 ÷ 2220 = 5.61、モデル 11134.5 ÷ 2415.9 = 4.61。7700 は実測 6.15・モデル 6.05 で合う。**7840HS の MT/ST はモデルが約 18% 低い**。
- 同じ 35〜54W の 7735HS(Zen 3+)は MT/ST が実測 4.55・モデル 4.45 で合い、連続式の標本の k_i も 0.391(中央値 0.4046 に近い)。7840HS だけが外れる。
- ST の u を下げると MT も同じだけ下がるので、MT は −14% 前後に悪化する(§5.3)。
- 7840HS の必要係数は約 0.82(u を変えないとき。連続式の 0.737 の約 1.12 倍)。連続式で W に換算すると約 110W 相当で、公表の 54W では説明できない。Phoenix の全コア負荷時のクロックが、連続式(Intel と Zen 3 が中心の 11 件で決めた)の想定より高い可能性がある(未確認)。
- 結論: MT 固有。必要なのは Phoenix の全コア負荷時の実測クロック(レビューの Cinebench などの全コアクロック。`allCoreGHz` に [二次] で入れられる形)で、今回は取っていない。

### 6.3 285H(MT +7.82%。ok)

ST の u × 0.92 で MT は +3.52% に下がる(ok のまま)。MT 固有の問題は見えない。

## 8. 影響を受ける他のプリセット

- 285H × 0.92: 285H だけ(新しい uarch 記録を使うのが 285H だけ)。Lion Cove の u・ほかの Arrow Lake(285K・265K・275HX)・Skymont の E は不変。
- HX × 0.94: 14700HX・14900HX・13980HX の 3 件(どれも ok の範囲内で動く。14900HX ST +8.18 → +1.69%、13980HX ST +6.98 → +0.56%)。Raptor Cove・Golden Cove のデスクトップ 10 件は不変(uCal は HX を除外済み)。c は不変だが、tests/perf.test.js の標本内 MAE・LOO の固定値は 14700HX の k_i が動くので変わる。
- 7840HS: 変更なしを推奨。

実装時は手本(70c4fb1)と同じく、blocklib の流用行・errCause・ratio の注記(RATIO_INFOS_UARCH)・旧保存データの移行・設計書 §5.3.0・テストの固定値とハッシュの更新が要る(本調査では触っていない)。

## 9. 限界(必ず併記)

1. **Intel の Maximum Frequency はほぼ一定の申告値で、動作クロックではない**(§3)。Intel の比は「同じ申告クロックあたりの ST」の比で、手本(AMD)ほど「動作クロック基準」になっていない。ARK の P コア最大ターボとも 0.2GHz ずれる SKU がある(14700HX 5287MHz 対 ARK 5.5GHz)。
2. **比には DRAM 遅延の代用 [推定] が混ざる。** 285H の 148ns は 155H の代用、HX の 82.1ns は 12600K の代用(デスクトップと同じ値)。遅延の絶対値が違えば比も動く。u と遅延を分けられていない。
3. **255H・8845HS・7700X は検索結果の集計でプリセットではない。** 255H・7700X・8845HS のモデル値は、285H・7700・7840HS の構成でクロックだけ替えた仮の計算(255H は P のクロック 5.1GHz、7700X は 5.4GHz。どちらも Max Freq の中央値に近い定格の値で、ここでは ARK・AMD 公式の再確認はしていない)。
4. **基準の選び方で比が 1〜3 ポイント動く。** 285K と 265K で約 0.7 ポイント、14700K と 14900K で約 3 ポイント、7700 と 7700X で約 1.5 ポイント。
5. 比を取った母集団(Windows・しきい値つき)と、誤差の判定に使う公開値の母集団は少し違う(285H は全 Win の ST 中央値 2436.5 に対し公開値 2420)。
6. 機種の偏りは機種数だけで確認(14700K は 146 件で 20 機種と少なめ)。
7. 7840HS・14700HX の MT 固有の原因(全コアクロック・電力設定)は未取得のまま。

## 10. 待ち(次に取ると良いもの)

- Phoenix(7840HS)の全コア負荷時の実測クロック(レビュー [二次])。取れれば `allCoreGHz` で MT を直せるか試算できる。そのとき ST の u × 0.95 前後も一緒に検討できる。
- 14700HX の投稿機の電力設定の分布(PL1/PL2)。
- Arrow Lake-H・Raptor Lake-HX の DRAM 遅延の実測(取れれば u の比と遅延を分けられる)。
- Intel の GB「Maximum Frequency」の出どころ(ARK と 0.2GHz ずれる理由)。

## 11. 実装結果(2026-11-15・285H と HX の 2 件を実装。7840HS は変更なし)

推奨セット(§0)をそのまま実装した。比・試算は §4・§5 のとおりで、実装後の全プリセットの再評価で試算と一致した(`tools/validate-data.js` OK、全テスト通過)。

| SKU | ST 前 → 後 | MT 前 → 後 |
|---|---|---|
| Core Ultra 9 285H(uarch「Lion Cove (Arrow Lake-H)」= Lion Cove の u × 0.92。P コアだけ) | +11.49% → **+2.57%**(ng → ok) | +7.82% → +3.52%(ok) |
| Core i7-14700HX(「Raptor Cove (HX)」= Raptor Cove の u × 0.94。P コアだけ) | +11.14% → **+4.47%**(ng → ok) | +17.14% → **+12.83%(ng のまま)** |
| Core i9-14900HX(同上) | +8.18% → +1.69% | +5.98% → +2.52% |
| Core i9-13980HX(同上) | +6.98% → +0.56% | +5.63% → +2.19% |

- ほかの 102 プリセットは ST・MT・誤差とも完全一致(106 件の前後比較)。285K・265K・275HX・Lunar Lake・Skymont の E、14700K などのデスクトップ、Raptor Cove の uCal 116.4 は不変。
- **延べ ng(158 件の数え方。ST と MT の延べ)は 11 → 9**(ok 147 → 149。ng→ok は 285H の ST と 14700HX の ST の 2 件、ok→ng は 0 件)。§0・§5 の「延べ ng 7 → 6」は数え方が違っていた(7 は前提とした数え方での値で、158 件の数え方では 11 → 9)。
- 連続式の c は 0.405 のまま(中央値 0.4046。14700HX の k_i は 0.3354 → 0.3505 に動くが中央値の下のまま)。標本内 MAE 0.0639 → 0.0600、LOO MAE 0.0700 → 0.0660、一律 0.81 の MAE 0.0805 → 0.0768。
- 面積の表: 「Raptor Cove (HX)」は「Raptor Cove」と同じ値の流用行(blocklib 32 → 33 件)。285H の Lion Cove は compute タイルのプロセスが未取得で元から面積の表に当たらず不明のままなので、行は足していない。

実装で守った限界(§9 のとおり):

1. **Intel の結果ページの Maximum Frequency は動作クロックではなく、数十機種でほぼ同じ申告値**(285H は 5386MHz が 147/151 件、14700HX は 5287MHz が 150/156 件)。点/GHz は実質「ST の中央値 ÷ 一定値」で、比は兄弟 SKU から取り、対象自身(285H・14700HX)は追認だけにした。
2. 比には DRAM 遅延の代用 [推定](285H の 148ns は 155H の値、HX の 82.1ns は 12600K の値)が混ざり、分離できない。
3. 255H・14900HX・13980HX・14700K・14900K の値は検索結果の集計で、`gb7-scores.js` の公開値の行ではない(255H・14700K・14900K はプリセットですらない)。
4. HX の比は基準の取り方で 0.93〜0.96 と動く。
5. **14700HX の MT(+12.83%)が ng のまま残るのは、IPC では直らないため**(P コアにしか効かない上、同じ 157W の 14900HX・13980HX は +2.5%・+2.2% で合うので、14700HX の投稿機の電力設定の疑い。未確認)。
6. **7840HS は変更しない**(u を下げると ng の MT が悪化する。MT 固有の問題)。
