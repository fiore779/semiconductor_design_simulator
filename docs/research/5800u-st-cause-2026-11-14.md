# Ryzen 7 5800U の ST 過大: 原因の特定と修正案(2026-11-14)

- 対象: プリセット `amd-zen3-5800u`(Cezanne、Zen 3、8c/16t、cTDP 10〜25W、ブースト 4.4GHz、L3 16MB)。
- 現在の作業ツリーでの予測(`tests/evaluate.test.js` の `ev()` と同じ読み込みで実行。2026-11-14): **ST 1941 / 公開 1614 = +20.3%、MT 7881 / 公開 6472 = +21.8%**(依頼文の MT +20.6% とは 1.2 ポイント違う。別担当の編集中の状態による差と考えられる。推測)。校正値: Zen 3 の u = 105.73、σ = 0.03183、γ = 0.30、連続式 c = 0.411・指数 0.15。全 158 判定のうち ng 24。
- **コード・データ・設計書は変更していない(試算のみ)**。使い捨てスクリプトは scratchpad の `base.js`・`exp.js`・`exp2.js`・`exp3.js`・`exp4.js`。
- 取得方法: Geekbench Browser(`https://browser.geekbench.com/v7/cpu/search?q=<SKU>`。Chrome の通常閲覧。WebFetch は 403)。検索結果の一覧(25 件/ページ)と、個別の結果ページ(`/v7/cpu/<id>`)の System Information を読んだ。ダウンロードはしていない。取得日はすべて 2026-11-14。
- 区分: [実測] = Geekbench Browser の投稿の値・その中央値、NBC の測定値。[公表] = AMD の仕様。[二次] = レビュー・集計サイトの記述。[推定] = モデル計算と、そこから導いた比。

## 0. 結論(要約)

1. **5800U の公開値は取り直しても変わらない**: Windows のみ・全件 n=76、ST 1614 / MT 6471.5(前回 2026-11-13 と同じ。新しい Windows 投稿は 0 件)。公開値の取り違えではない。
2. **原因は 2 つに分かれる**(ST の過大 +20.3% = 対数で 0.185):
   - **(A) Cezanne(APU)の ST は、同じ Zen 3 の u(代表 5800X)で計算すると約 5% 過大になる**(対数で約 27%)。デスクトップの Cezanne(5600G・5700G。電力制限もノートの母集団も無い)でも、同じモデルで **+4.6%・+5.8%** 過大になる [実測と予測の比較]。内訳は、5800X が公称ブースト 4.7GHz を超えて動いている分(結果ページの Maximum Frequency の中央値 4840MHz)が約 2.7 ポイント、残り約 2.6〜3.4 ポイントが Cezanne 固有(L3 16MB の効きがモデルより大きい、など。[推定])。
   - **(B) Windows 投稿の 7 割は 4.4GHz に届いていない**(対数で約 66%)。結果ページの Maximum Frequency は、76 件の中央値が **4064MHz**、4400MHz 以上は 21 件(28%)だけ。4400MHz 以上の 21 件(10 機種)の中央値は **ST 1823 / MT 7527** で、全体の中央値より ST +13.0%、MT +16.3% 高い。1 機種(HP ProBook x360 435 G8。2026-10-17〜18 の 20 件、すべて 4064MHz・電源プランは「バランス」)が全体の 26% を占める。
   - (A) を入れた予測(ST 1844 / MT 7486)は、4.4GHz に届いた投稿の中央値と **ST +1.2%、MT -0.5%** で一致する。**モデルのチップ単位の残りはほぼ 0** になる。
3. **否定された候補**: 「15W 級は ST のブーストを保てない」(4.4GHz に届いた 5800U は 1823、同じ 4.4GHz の 45W 機 5800H は 1833 で差が無い)。「搭載機の多くは LPDDR4X」(76 件のうち LPDDR4X-4266 は 8 件だけ。DDR4-3200・2ch が 56 件)。
4. **推奨**: 出典のある補正は (A) だけ。**Cezanne 用の uarch 記録を分け、u を Zen 3 の 0.95 倍にする(根拠はデスクトップ APU 5600G・5700G の Windows 中央値。[実測] から導いた [推定・校正値])**。5800U は ST +14.3%・MT +15.7% になる(どちらも ng のまま)。残りは母集団の差 (B) で、5800U だけに係数を作らず、モバイル x86 全体の扱い(`mobile-st-cause-2026-11-13.md` の係数 0.90。ユーザー判断待ち)に任せる。両方を入れると **ST +3.8%(ok)**、MT は +15.7% のまま。
5. **「ST を直せば MT も直る」について**: 誤差の大きさとしては正しい(MT ÷ ST の比の誤差は +1.2% だけ。MT の過大の 94% は ST と共通)。ただしモデルの仕組みでは、MT に伝わるのは u を通る (A) の約 5 ポイントだけ。(B) は ST 専用の係数では MT に伝わらない。**MT を ok にする出典つきの補正は、今回は見つからなかった。**

## 3. L3 16MB(単一 CCX)の扱いと兄弟との比較

### 3.1 モデルの扱い(`js/sim/perf.js`。確認済み)

- L3 の容量は `cfg.l3MB` から入る。ST は 1 スレッドが 1 CCD 分を使う(5950X は 64MB ÷ 2 CCD = 32MB)。L3 ミス率 = `mpkiL3 × (容量 ÷ 2MB)^-0.5`(√2 則。**mpkiL3 = 0.9 は校正前の仮の値**)。
- L3 の遅延は uarch の `l3Lat`(Zen 3 は 46 サイクル)で、**Vermeer と Cezanne で同じ値**。DRAM 遅延は 85ns で共通(5800U の基準は DDR4-3200 で、補正は 1)。
- したがって Cezanne と Vermeer の差としてモデルに入っているのは、L3 容量の 1 項だけ。

| SKU | ブースト | ST の L3 | 予測 ST | L3 を 8 / 16 / 32 / 64MB にしたときの ST の変化 [推定] | メモリ項の CPI |
|---|---|---|---|---|---|
| 5800U | 4.4 | 16MB | 1941 | -3.7% / 0 / +2.8% / +4.9% | 0.0840 |
| 7735HS | 4.75 | 16MB | 2080 | -4.0% / 0 / +3.0% / +5.3% | 0.0858 |
| 5800X | 4.7 | 32MB | 2122 | -6.7% / -2.9% / 0 / +2.2% | 0.0785 |
| 5600X | 4.6 | 32MB | 2080 | -6.6% / -2.8% / 0 / +2.1% | 0.0782 |
| 5950X | 4.9 | 32MB(64MB ÷ 2) | 2206 | -7.0% / -3.0% / 0 / +2.2% | 0.0793 |

- **モデルは L3 16MB と 32MB の差を ST で -2.7〜-2.9% として取り込んでいる**(同じクロックでの IPC の比。3.0GHz で -1.9%、4.4GHz で -2.7%、4.7GHz で -2.9%)。MT では L3 を 2 倍にすると +6.4〜7.9%。

- 内訳([推定]):
  - **5800X は公称 4.7GHz より高く動いている**(Maximum Frequency の中央値 4840MHz。5600G・5700G・5800U はほぼ公称どおり)。モデルは公称ブーストで u を決めるので、Zen 3 の u は約 2.7% 高く出ている(ST のクロック弾性 0.91 での計算)。これは `mobile-st-cause-2026-11-13.md` §2.5 の「Zen 3 の代表の偏り 約 3 ポイント」(5600X +3.0%、5950X +4.3%)と同じ大きさで、その原因の候補になる。
  - 実クロックにそろえても **5600G +2.6%、5700G +3.4% が残る**。これが Cezanne 固有の分で、L3 16MB の効きがモデルの -2.9% より大きい(合計で約 -6%)と読める。メモリの差もありうる(デスクトップ APU の投稿は DDR4-2400〜2700 や 1ch が多い。DDR4-3200 以上・2ch に限ると 5700G 1931.5〔n=20〕、5600G 1872〔n=15〕、5800X 2133〔n=27〕で、比は 0.906 と 0.878 → 結論は変わらない)。
- mpkiL3 を全体で大きくする試算(u は 5800X で取り直す): ×3 で 5600G +0.8%・5700G +1.4%、×4 で -0.6%・-0.3%。Zen 3 の対だけなら ×3〜4 で合う。ただし全 SKU の L3 感度が変わる(§4 の案 D)。

補足:

- A の後の 5800U を、Windows 投稿の Maximum Frequency の中央値 4.064GHz で計算すると ST 1716(+6.3%)。4.4GHz に届かない投稿は、その上限よりさらに低く走っている(4000〜4199MHz の 29 件の中央値 1571)。
- A を 7735HS に当てるかは別の判断。7735HS は Zen 3+(6nm、DDR5、L3 16MB)で、デスクトップの対照が無い。同じコア・同じ L3 構成なので当てるのが自然だが、根拠は Cezanne からの流用になる([推定])。
- 同じ構図は Zen 4(7840HS・Phoenix 16MB と 7700・32MB)にもありうる。デスクトップの 8700G が対照になる(今回は未取得)。

### 4.1 推奨

1. **A を実装する**(Cezanne の u = Zen 3 の u × 0.95)。出典つきの補正で、5800U の公開値に合わせた係数ではない(根拠は別の SKU 2 件)。
2. 残りの +14.3% は母集団の差で、**5800U 固有の係数は作らない**。B(モバイル x86 の ST 係数)を採るかどうかの判断に任せる。B を採れば ST は +3.8% で ok。
3. 5800U の errCause(ST・MT)の文面を、今回の分解に更新する候補(旧文面は「15W 級で ST が 4.4GHz に届かない可能性」「LPDDR4X」を候補にしている)。`gb7Ref` に「4.4GHz に届いた投稿 21 件の中央値 1823 / 7527 [実測]」を参考値として足す候補(現在の推定 1690 / 8880 は GB6 の転載 1 件から出した弱い値)。

## 5. MT の誤差の分解

| 項目 | 値 |
|---|---|
| ST の誤差 | +20.3%(対数 0.185) |
| MT の誤差 | +21.8%(対数 0.197) |
| MT ÷ ST(予測 / 公開) | 4.059 / 4.010 → **比の誤差 +1.2%** |
| MT の過大のうち ST と共通の部分 | 対数で **94%** |
| MT に固有の残り | 約 1.2 ポイント |

- **誤差の大きさで見れば、ユーザーの見立てどおり MT の差はほぼ ST の差だけ**。MT 固有の残りは 1.2 ポイントで、MT の連続式(25W で係数 0.666、全コア 2.93GHz)は 5800U の MT ÷ ST の比をほぼ正しく出している。
- ただし、モデルの仕組みで MT に伝わるかどうかは原因ごとに違う:

| ST の過大の原因 | ST への寄与 | MT に伝わるか | MT の変化 |
|---|---|---|---|
| (A) Cezanne の u(約 5%) | +20.3 → +14.3% | **伝わる**(MT も同じ u を使う) | +21.8 → **+15.7%** |
| (B) 母集団(4.4GHz に届かない投稿が 72%) | 残り +14.3% | **ST 専用の係数では伝わらない**(MT は自分のクロック係数 c を使い、c は別の標本 11 件の MT から決めている) | +15.7% のまま |

- (B) は MT の側にも同じ大きさである(4.4GHz に届いた投稿の MT 中央値 7527 は全体より +16.3%。ST は +13.0%)。A を入れた MT の予測 7486 は、4.4GHz に届いた投稿と -0.5% で一致する。つまり **MT の残り +15.7% も、モデルの欠陥ではなく母集団の差**。他のモバイルではこの差を c が吸収しているが、5800U は届かない投稿の割合が高く、吸収しきれていない([推定])。
- 公開値と一致する MT のクロック係数は 0.52(全コア 2.30GHz)で、モデルの 0.666 より低い。A の後でも約 0.55 が必要(クロック弾性 0.91 での概算。[推定])。
- **結論**: ST を A で直すと MT は約 6 ポイント下がる。ST を B(ST 専用の係数)で直しても MT は下がらない。MT を ok にするには、(B) を MT にも掛ける扱い(モバイルの c の標本と再校正の見直し)か、公開値の定義の見直し(案 F を全 SKU で行う)が要る。どちらも 5800U だけの話ではなく、今回の範囲では提案しない。
